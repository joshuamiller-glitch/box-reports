Code: `outputs/code/th_bars/kernels.py` `k_renko` lines 59-94; box and parameters `outputs/code/th_bars/build_month.py` lines 108-113 (row `renko`: b = B, R = 2B, O = B, wick 0; B = `np.maximum(2, np.round(p * S['rng']))` ticks with p = 14 and S['rng'] = s_rng of the print's trading date, line 111); scale `scales()` lines 13-32; session split `common.py` lines 10-17 (ET: code 0 Asia 18:00-02:00, 1 London 02:00-08:30, 2 pre 08:30-09:30, 3 NY AM 09:30-12:00, 4 NY PM 12:00-16:00, 5 close 16:00-18:00; td = ET + 6 h; session id td x 10 + code).
1. Input = every trade record (one row per trade, no merge). Renko is UNAFFECTED by the D8 print/run-merge rule (D8_PRINT_RULE.md section 5: 100.00% of run-merge bricks equal the old-engine bricks in O/H/L/C and close time, month 2026-10), so the stored bars `/mnt/l2/l2vast/_bars/renko_14` stand.
2. BRICK SIZE B = max(2, round(14 x s_rng)) ticks of 0.25 point, numpy rounding (round half to even), fixed for the whole trading date td (the same value for Asia, London, pre, NY AM ... of that td; s_rng is looked up by the print's td). s_rng = trailing median of the 20 previous stats_day rows of the daily range / r0 (r0 = 191.5 points) as in D8_ASIA_NEWBOOK_INPUTS.md sections 2 and 3 (scales() code, rule of the range rows: stats.py lines 13-18). Values: td 20261027 s_rng 2.189948 -> B = 31 ticks = 7.75 points; td 20261110 s_rng 3.048303 -> B = 43 ticks = 10.75 points (engine store as it is; hole-filled alternatives in 4).
3. State per (session key, instrument id): at the first print of a session (or after an instrument change) the state starts: bo = bc = that print's price, direction d = 0, nothing emitted (kernels.py lines 66-70). The state is RESET at every session boundary and contract change, the unfinished brick is dropped: THE ENGINE EMITS NO PART = 1 BRICK (no truncated last brick); all bricks have part = 0.
4. First brick (d = 0): print p >= bo + B -> UP brick [bo, bo + B], d = +1; or p <= bo - B -> DOWN brick [bo, bo - B], d = -1 (the first print price is the reference, not a grid).
5. Continuation: d = +1 and p >= bc + B -> next UP brick [bc, bc + B] (bc = last brick close); d = -1 and p <= bc - B -> DOWN brick [bc, bc - B].
6. Reversal (classic Renko, R = 2B, O = B): d = +1 and p <= bc - 2B -> a DOWN brick that OPENS at bc - B and CLOSES at bc - 2B (height B); d = -1 and p >= bc + 2B -> an UP brick opening at bc + B and closing at bc + 2B. (A reversal therefore needs the price to travel 2B from the last close; the new brick starts one B back from it.) The reversal test is only made when the continuation test failed (elif).
7. One print may complete several bricks: the loop (line 75) re-tests the same print until no more bricks form; every brick gets the same known time (the print's timestamp); the first brick of the print takes the accumulated volume of the prints since the last brick, the following ones zero volume (vol reset at line 92).
8. Brick OHLC: open = no, close = nc, high = max, low = min (no wick: wick = 0). Volume = sum of `sz` of the prints since the previous brick incl. the completing print; known time (t_close) = timestamp (ts_event) of the completing print; t0 = the print after the previous brick's completion (equals the previous brick's known time; for the first brick of a session the first print).
9. Series seen by the trigger: ALL sessions of all history concatenated in known-time order as one series (D8_BAR_DEFS.md section 2; engine loader outputs/code/th_grid/gjob.py lines 33-49). The brick height is constant within a td, but changes at a td change.

2. LINE LOOKUP at bar j: T0_j = floor to whole seconds of the KNOWN time of bar j-1 (no t_open in the series; bar 0 has none); the line value = the line entry of the last 1-minute start <= T0_j, valid only if T0_j - that minute start <= 120 s, else NaN (fd_common.line_index lines 29-33). The bar's own close (known at t_close[j]) is compared with that frozen level.
3. UNIT (native): u_j = median of (high - low) in POINTS of the previous 100 bricks of the continuous series (bars j-100 .. j-1, the CURRENT bar excluded, min 20 bars), floor 0.5 point (fd_common.unit lines 38-45). Within a td u equals the brick height once 100 bricks of that td exist (7.75 or 10.75 points on the parity days); at the first bricks of a td it mixes the previous td's brick heights.
4. BREAK n = 3, k = 0.25: for each line L (value at bar j's T0) with ku = 0.25 x u_j: UP condition at bar j = close_j > L + ku; LONG event at bar j when the closes of bars j, j-1 and j-2 are ALL > L + ku (each compared with the SAME L and ku of bar j) AND the close of bar j-3 was <= L + ku ("fresh"), and the event is an EDGE (not also true on bar j-1). Strict comparisons. SHORT mirrored: closes of j, j-1, j-2 all < L - ku and close_{j-3} >= L - ku, edge. Both masks are OR-ed over the six lines; a bar with a long on one line and a short on another is dropped; the "fired line" = the first line in the list order with an event at that bar (information only, not used by the order). Bars whose line or u is NaN cannot fire.
5. Computed at the brick close (known time); no look-ahead. Warm-up for a coder: 100 prior bricks for u (min 20) and 4 prior closes.
Units: line and u in points (NQ).

## 5. Level lines: how they are built, and the 45-day table (as stored and hole-filled)
Code: `outputs/code/th_grid/triggers_d/fd_profile.py` lines 20-28 (value area), 40-63 (daily profile), 65-71 (5-day composite), 72-85 (broadcast to the next label day); minute store `/mnt/l2/l2vast/_bars/feat_d/nq1m.npz`, line files `/mnt/l2/l2vast/_bars/feat_d/lines/PRF{1,5}__{POC,VAH,VAL}.npy` (raw price per minute, adj - roll offset). Rules:
1. Histogram: every trade record of the regular session of one ET day, 09:30:00 to 15:59:59 ET, volume (contracts) per price row, bin = ONE tick (0.25 pt), prices back-adjusted to the newest contract by that day's roll offset (0 in October-November). Days with fewer than 1,000 RTH prints are skipped.
2. POC = row with the highest volume (first one if tied). Value area 70%: start at the POC row (accumulated = its volume); while accumulated < 0.7 x total and room remains: compare the volume of the next TWO rows above the top (rows b+1..b+2) with the next two rows below the bottom (a-2..a-1) (a missing side counts as -1); take the larger sum (upper pair if equal), add it, move that edge by two rows (clipped at the ends). VAH = top row, VAL = bottom row (so the area can overshoot 70%).
3. PRF1 = POC/VAH/VAL of the previous data day's RTH; PRF5 = the same on the sum of the histograms of the last 5 data days with an RTH profile (the day itself and the 4 before it, in the data as stored; holes make the window reach back further). Values in points.
4. Availability: the lines of RTH day d apply to the WHOLE next trading date (label day) from its first minute (18:00 ET the evening before), constant through it (e.g. td 20261110 uses the RTH of 20261109). 
5.
