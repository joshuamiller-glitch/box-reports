Written for order 20261120_1351Z section C items 2 and 3. Research artefact only. Source of truth = engine code under outputs/code/th_grid (+ th_swap, triggers_b/c/d); nothing was edited. Pool = own-checks passers (Asia 29 per ALL_NEW_STACK_ASIA_OWN_CHECKS.md, NY AM 8 per ALL_NEW_STACK_NYAM_OWN_CHECKS.md). Book parameters are the 'what-it-is' column of /mnt/l2/l2vast/_split/best_books_*_full.csv. Bar construction is on D8_BAR_DEFS.md (written by the parent agent); this page assumes the bar series as given.
Sample trading dates 2026-11-09, 11-10, 11-11 (trading date = ET + 6 h; Asia = session code 0 = 18:00 ET previous evening to 02:00 ET; NY AM = code 3 = 09:30-12:00 ET). Data end of the stored bars/events: 2026-11-13.

## 0. What the test vectors are (read this first)
- Files: autopilot/d8_testvectors/triggers/<cell>_signals.csv, 37 files, columns kind(raw|event), ts_utc_iso, side (+1 buy, -1 sell), bar_sess_id (trading date x 10 + session code of the signal bar for raw; of the event timestamp for event).
- kind=raw: the module's signal_fn called on the full stored bar series of the book's row (all history from 2023-04, one continuous series, all sessions, exactly as code/th_grid/gjob.py does), then kept if the signal bar is in the book's session on a sample date and part==0 (a truncated last bar of a session never signals). ts = bar t_close = the time the bar is known complete (event bars: timestamp of the closing print; time bars: first print of the next bucket, see bar page). This is the SIGNAL time.
- kind=event: the traded-event list from the engine events file (/mnt/l2/l2vast/_asi_lad/ev or _nye/ev, column ts in whole seconds). 
- RESULT: on all 37 books and 1,750 sample-day events, EVERY event matches exactly one raw signal of the same side, and the event ts is raw ts + 2 s in all cases except 2 (L3faac8df: one at +1 s; L2176f633: one at +0 s; both look like second-rounding at the boundary). Raw count equals event count for 34 of 37 books; the other 3 (M3f6f752c, M7423c0d9, L05350e98) are long-only: the module emits both sides, the events file keeps the long side only (M-id = long-only rebuild of the L-id; L05350e98 is an L-id whose events are long only as well; its raw longs, 6, equal its 6 events). So the trigger side of the engine is fully reproduced by the stored modules on these days.
- The events file is NOT one-position-at-a-time: in Ldcdb0b6e 6,204 of 7,131 events start while the previous event is still open (exit_ts later than the next ts); in L7f41b347 52,917 of 53,851. Each signal is scored with its own bracket. Position blocking, session lots, locks, caps happen in the later layers, not in the trigger. A D8 coder must therefore not expect the trigger list to be a trade list.
- The fill is NOT in the trigger: entry = first print strictly after signal ts + 1 s (+ measured slippage) in the harness. The 2 s offset in the events file is the label the events file carries for the entry time; the exact fill rule is outside this page.

## 1. Conventions common to every trigger
1. Input = the bar series of the book's row, ONE continuous series sorted by t_close over ALL sessions since 2023-04 (indicators carry state across session breaks and weekends; only the session filter and the part==0 filter are applied to the SIGNAL bar). o,h,l,c in points; v = bar volume; dlt = signed volume; sess_id; spb = seconds per bar (stored; for event bars = seconds since the previous bar's last print within the session, else bar duration).
2. Output = bar index where an edge event occurs; side +1 buy / -1 sell. A bar that is both long and short is dropped. Fires at bar close (known at t_close). No look-ahead (the harness runs a causality test on every module).
3. Warm-up is only from indicator definitions listed per trigger, plus the global fact that the series starts 2023-04-02. Early signals on a short NT8 chart will differ until the indicator state has converged (EMA seeds: first close).
4. 'Native' variants (name ends _native): on TIME bars they equal the plain variant for momentum/trend modules (no change), but NOT for bands/levels/book modules (see the module sections). On activity/price/information bars they use constants taken from the FIRST 2000 BARS OF THE STORED SERIES (from 2023-04-02): median seconds per bar, brick size, etc. NT8 cannot recompute these chart-free; they must be hard-coded. The values the engine used are in section 4. No native signal is emitted before bar 2000 of the series.
5. Roll handling differs by family and is easy to miss: triggers_b modules (pullback_ema, structure_*) back-adjust bar prices at contract rolls using the stored bar iid (no iid for tm* rows, so no adjustment there); round-number levels are computed on the RAW price (c - adjustment). The W-GRIDA modules (momentum, bands, trend) use raw stored prices with no adjustment, so a roll gap sits inside the series as a one-bar jump. Level modules read lines built from a back-adjusted 1-minute store converted back to raw price at each minute.
6. Python round() is banker's rounding (round half to even); lookbacks below were computed with it (e.g. 7.5 -> 8, 0.5 -> 0).
7. The ID of a book such as 'L578701ed' is the L-id (both sides unless said); 'M' ids are the long-only rebuild.

## 3. Trigger definitions (from the code)
Notation: c,h,l,o = bar close/high/low/open in points of the book's bar series; i = current bar; EMA(n) alpha = 2/(n+1) seeded with the first value of the series (first non-NaN) unless stated; 'edge' = event only on the first bar where the condition becomes true (condition true now, false on the previous bar).

### 3.1 trig_momentum_mvote (momentum vote, M7 generalised) [th_grid/trig_momentum_mvote.py]
Books: Ldcdb0b6e (cdr_100 v3of5 scale .25 thr .25; Asia stack), L7ea48296 (cdr_100 v4of5 .25/.25), L15f14deb (tm120 v4of5 .25/.25), L29b1bc3f (vsess_80 v5of5 .25/.25), Lbe5ac95b (vsess_50 v4of5 .25/.25), L40bde9ea (vsess_120 v4of5_native scale 1.0 thr .25), Lc4584864 (tick_500 v3of5_native .25/.25).
Formula (plain). Base lookbacks b in (15,30,60,120,240) bars. L_k = max(round(b_k * scale), 2). d[i] = c[i]-c[i-1] over the continuous series (d[0]=0). For each L_k: W = max(L_k, 120); sigma = SAMPLE std (divisor W-1) of the last W values d[i-W+1..i] (current bar included; computed as (sum d^2 - W*mean^2)/(W-1)); z = (c[i]-c[i-L_k]) / (sigma*sqrt(L_k)); skip the lookback while i <= max(L_k, W) (i <= 120 or i <= L_k) or sigma <= 0. Vote +1 if z >= thr, -1 if z <= -thr. k[i] = sum of the 5 votes (range -5..+5). Votes needed V = 3 (v3of5), 4 (v4of5), 5 (v5of5). LONG event on bar i when k[i] >= V and k[i-1] < V (edge); SHORT when k[i] <= -V and k[i-1] > -V.
Pool parameter values (scale .25): L = (4, 8, 15, 30, 60) bars, all with W = 120. Warm-up: first 121 bars of the series.
Native (activity bars: vsess, tick, vol, cdr counted as activity in the registry): bars are replaced by a unit-volatility price series q = cumsum( d / sg ), sg[i] = max( sqrt(EMA200(d^2))[i], 0.1*s0 ), EMA200 = EMA with alpha 2/201 seeded with its first value, s0 = RMS of d over bars 1..1999 (constants section 4). The votes use q instead of c, with lookbacks in CLOCK MINUTES: L_k = clip(round(b_k*scale*60 / med), 2, 5000), med = median seconds-per-bar (spb) of the first 2000 bars. No signal before bar 2000. L40bde9ea (scale 1.0, med 86.176 s): L = (10, 21, 42, 84, 167), W = (120,120,120,120,167). Lc4584864 (scale .25, med 52.222 s): L = (4, 9, 17, 34, 69), W = 120. Because q is a cumulative sum, only differences matter; the absolute level of q is irrelevant to z.
Data: bars only. Fires at bar close.
NT8: straightforward on the bar series (needs the 120-bar sample std and the vote counter). Native variants need the two hard-coded constants (med spb, s0) and an EMA200 of d^2 running over the chart history (its seed effect has decayed; 3.5 years of history).

### 3.2 trig_momentum_roc (ROC z-break) [th_grid/trig_momentum_roc.py]
Books: Lcae177ba (vol_1100 break len 10 wd 1.0), L488784d8 (swing_atr_0.25 break_native len 20 wd 1.0; NY AM Stack A).
Plain: n = max(round(len),2); ch[i] = c[i]-c[i-n]; sigma = sample std (divisor W-1) of the last W = max(n,60) values of d (current included); z = ch / (sigma*sqrt(n)); LONG event when z crosses up through +wd (z[i-1] <= wd and z[i] > wd); SHORT when z crosses down through -wd (z[i-1] >= -wd and z[i] < -wd). Warm-up: first 61 bars.
Native on PRICE bars (swing family, L488784d8): q = cumsum(d * k), k[i] = w[i]/size, w[i] = clip(EMA200(spb)[i] / spb[i], 0.25, 4.0) (fast bricks weigh more), size = median |d| (nonzero, bars 1..1999) = 8.0 points for swing_atr_0.25; spb floor 1e-3 else filled with the median spb of the first 2000 bars; q replaces c, h and l are carried as q + (h-c)*k, q - (c-l)*k; lookback n = round(len) = 20 bars (price bars use bars as unit); W = 60. Same cross rule on z computed on q. No signal before bar 2000. The stored spb of the swing bars is an input (seconds since previous bar's last print inside the session; first bar of a session: bar duration).
NT8: native variant needs per-bar seconds between bars (bar close time minus previous bar close time within session) and the constants.

### 3.3 trig_momentum_stoch (stochastic zone break) [th_grid/trig_momentum_stoch.py]
Books: Lda55d973 (vol_750 zone_break_native len 9 lvl 80), L973b5c8a (tm420 zone_break_native len 21 lvl 80).
K = 100*(c - LL)/(HH - LL) with HH = highest high and LL = lowest low of the last n bars including the current bar (NaN while fewer than n bars or HH==LL); D = SMA3 of K (not used for zone_break). zone_break: LONG event when K crosses up through lvl (K[i-1] <= lvl and K[i] > lvl); SHORT when K crosses down through 100-lvl (K[i-1] >= 20 and K[i] < 20).
Lda55d973 native on activity bars: stochastic of q (same q as 3.1: unit-volatility series with h/l carried), n = clip(round(9*60/40.666),2,5000) = 13 bars; no signal before bar 2000. L973b5c8a: tm420 is a TIME row, so native = plain: n = 21 bars of 7 minutes, no constants, warm-up 21 bars.
Data: bars only.

### 3.4 trig_bands_bollinger break (L86781ac0, vrb_700, n 20, k 1.5) [th_grid/trig_bands_bollinger.py + bandlib_wgrida.py]
mid = SMA(c, 20); s = POPULATION std (ddof 0) of the last 20 closes; up = mid + 1.5 s, lo = mid - 1.5 s. LONG event on the first bar whose close is above up (close > up now, not on the previous bar); SHORT on the first bar whose close is below lo. Bars without a defined band are never outside. Warm-up: 20 bars. Data: bars only.

### 3.5 trig_bands_keltner walk (Lc849eb8c, dlt_70, ema 30, atr 10, mult 1.5, N 3) [th_grid/trig_bands_keltner.py]
mid = EMA(c, 30); ATR = Wilder RMA(10) of the true range seeded with the SMA of the first 10 TRs (ind.rma; TR_i = max(h-l, |h-c[i-1]|, |l-c[i-1]|) with c[-1] = c[0]); up = mid + 1.5*ATR, lo = mid - 1.5*ATR. 'walk' with N=3: LONG event on the bar that is the 3rd CONSECUTIVE close above up (the run length equals exactly 3; the 4th, 5th bars do not fire again); SHORT on the 3rd consecutive close below lo. Warm-up about 10 bars for ATR (value NaN before) but the run logic needs a defined band. NOTE: this ATR is the th_grid/ind.py version (SMA-seeded Wilder); k7 uses a different seed (first TR), see 3.8. Data: bars only.

### 3.6 trig_bands_vwap walk_native (Lb68a132d, tm600, clk 6, k 1.0, N 2) [th_grid/trig_bands_vwap.py]
Session VWAP reset at every change of sess_id (Asia, London, pre, NY AM, NY PM, close each restart it): typical price tp = (h+l+c)/3, weights = bar volume; w = cumsum(tp*v)/cumsum(v); sd = sqrt(max(cumsum(tp^2 v)/cumsum(v) - w^2, 0)) (volume-weighted population sd of typical prices of bars). Bands up = w + k*sd, lo = w - k*sd, defined only after mb bars of the session have passed (count 0-based: bar number >= mb). Native: mb = max( clk_to_len(clk, sref)//2, 3 ), clk_to_len = clip(round(clk*60/sref), 3, 600), sref = median spb of first 2000 bars (tm600: 600.001 s) -> clk_to_len(6) = 3 (round(0.6)=1 clipped up to 3), mb = max(1,3) = 3. TIME family, so no brick floor. 'walk' N=2: LONG on the 2nd consecutive close above up, SHORT on the 2nd consecutive close below lo. Native warm-up rule: no signal before bar 2000 of the series (2023-04-21).
Data: bars with volume only.

### 3.7 trig_levels_* family (level triggers) [th_grid/triggers_d/lv_base.py, fd_common.py, fd_levels.py, fd_levels2.py, fd_profile.py, lv_fibleg.py]
Books: L7cc56d99 (lbrk_3_40 vwap break n 2 k .25; NY AM Stack A), L11152f7a (vol_350 vwap reject tol 1.0 conf body), La6f6f7ad (vsess_80 vwap retest_native M 3 tol .5), Lec335094 (tm780 vwap break_native n 1 k .25), L7f41b347 / Lff52ec0c (tm60 / time_m_1 fib15 break n 2 k .25), Lcbc8a7ec (tm60 fib15 break_native n 2 k .25), L3faac8df (mrenko_20 trendline break_native n 2 k 0), L2176f633 (dib_3500 profile_nodes false_break_native M 3 k .5), B6f77f23d (tm45 opens false_break_native M 3 k .5), B2010fec9 (vol_6000 opens retest_native M 10 tol 0), L05350e98 (tm420 session_hl retest_native M 3 tol 0).
A. Level lookup (applies to all). Lines are minute-grid arrays (feat_d/lines/<name>.npy) built from a 1-minute NQ bar store made from the tape (nq1m.npz: minute bars, back-adjusted for contract rolls, converted to RAW price at each minute). The value of line L at bar j = the line entry for the last minute whose START is <= T0_j, T0_j = t_close[j-1] (whole seconds; the stored frames carry no t_open, so the decision time is the PREVIOUS bar's close, even when bar j opened later). If that minute start is more than 120 s older than T0, the level is NaN. Line entry for minute i only uses minutes < i (or whole completed sessions/days). The bar's own o/h/l/c are then compared with the level frozen at T0_j.
B. Width unit u. Plain variants: u = 5.0 points. _native variants: u = rolling median of (h-l) over the last 100 bars shifted by one bar (bars i-100..i-1), min_periods 20, floor 0.5 points (NaN until 20 bars).
C. Event logic per line (fd_common.level_events); a bar's long/short mask is the OR over all lines of the set; the first line that fires is recorded; a bar with both long and short is dropped; every event is an edge.
- break(n,k): up = c > L + k*u; a long event needs the last n closes (bars j-n+1..j) all > L+k*u (each compared with the level of bar j) AND the close n bars back c[j-n] <= L+k*u (fresh), and then edge(). Short mirrored (c < L - k*u, c[j-n] >= L - k*u).
- reject(tol, conf): short if previous close pc < L, h >= L - tol*u, c < L (and for conf=body c < o); long if pc > L, l <= L + tol*u, c > L (conf=body: c > o). edge().
- retest(M, tol): k = 0 (the retest grid has no k); a break-up EDGE is edge(c > L); long if a break-up EDGE occurred within the previous M bars (j-M..j-1) and l <= L + tol*u and c > L and c >= o; short mirrored (a break-down edge within M bars, h >= L - tol*u, c < L, c <= o). edge(). Note the retest grid has no k: k = 0.
- false_break(M, k): up = c > L + k*u, dn = c < L - k*u (level-true, not edge); SHORT if up was true on any of the previous M bars (j-M..j-1) and now c < L; LONG if dn was true on any of the previous M bars and now c > L. edge().
D. The line sets (and the minute-grid rules). tord = minutes since 18:00 ET.
- vwap (8 lines): VWAP0 = VWAP from the 18:00 ET session start (minute typical price (h+l+c)/3 x volume, minutes before i), valid from tord>=30 and cumulative volume > 2000; RVWAP0 = from 09:30, valid 09:45-16:00; LVWAP0 = from 02:00, valid 02:15-16:00; YVWAP = prior RTH day VWAP (09:30-16:00) held for the whole next label day; AVPDH / AVPDL = VWAP anchored at the minute of the prior RTH day's high / low, running the whole next label day; WVWAP (ISO-week anchored, valid after 20000 volume), MVWAP (month anchored). In Asia only VWAP0, YVWAP, AVPDH, AVPDL, WVWAP, MVWAP can be non-NaN (RVWAP0/LVWAP0 are NaN before 02:15/09:45). In NY AM all eight are available.
- fib15 (9 lines FIB15_R236,R382,R500,R618,R650,R786,E1272,E1618,E2000): 15-minute bars aggregated from the 1-minute store (bucket = floor(ts/900 s); bar end = (k+1)*900 s); fractal pivots with strength k=2 (a high pivot at bar j: h[j] >= max of the 5-bar window h[j-2..j+2] and strictly the unique maximum; low mirror); a pivot counts only from the END of bar j+2 (confirmation); zigzag: confirmed pivots alternate high/low, a later pivot of the same type replaces the previous only if more extreme; leg = second-last to last pivot (B -> C, rng = C - B); retracement lines R_r = C - r*rng (r = .236,.382,.5,.618,.65,.786), extensions E_e = B + e*rng (e = 1.272, 1.618, 2.0); value stays until replaced, invalid after 10 days (14,400 minutes). Native only changes u.
- trendline (TL5_L, TL5_H, TL15_L, TL15_H): trendline through the last two confirmed pivot LOWS (kept only if ascending, slope > 0) or pivot HIGHS (only if descending, slope < 0) of the 5-minute / 15-minute bars (same pivots as above), extrapolated to the minute: value = p_last + slope*(ts - t_last), t = pivot bar centre = bar end - w*60/2 s, slope = (p_last - p_prev)/(t_last - t_prev); age limit 3*288*5 min (5m) / 10*96*15 min (15m).
- profile_nodes (10 lines): PRF1__HVN1,HVN2,LVN1,LVN2,SPH,SPL (prior RTH day, 09:30-16:00 ET prints) and PRF5__HVN1,HVN2,LVN1,LVN2 (5-day composite): tick histogram of volume; 70% value area by two-row expansion around the POC; HVN = the two highest local maxima of the histogram smoothed with a Gaussian (sigma 8 ticks, +-24 ticks) at least 8 ticks from the POC; LVN = two deepest local minima inside the value area; SPH/SPL = top/bottom of the longest run (>= 4 ticks) of price rows touched by exactly one 30-minute bracket (single prints). A day's profile is used from 18:00 ET that evening through the next RTH close. Needs the full tape (every print), not bars.
- opens (7 lines): T_P0930__P (open of the 09:30 minute; available from 09:31), T_P1000__P (10:00 minute open; from 10:01), OPEN_DAY__P (18:00 ET minute open; from 18:01), OPEN_0000__P (00:00 ET open; from 00:01), OPEN_0200__P (02:00 open; from 02:01), OPEN_WEEK__P, OPEN_MONTH__P (first minute of the ISO week / month, shifted one minute).
- session_hl (10 lines): S_ASIA__H/L (18:00-02:00, known from 02:00), S_LONDON__H/L (02:00-08:30, from 08:30), S_PRE__H/L (08:30-09:30, from 09:30), ON__H/L (18:00-09:30, from 09:30), S_NYAM__H/L (09:30-12:00, from 12:00). In NY AM only Asia, London, Pre and ON are available.
Warm-up: the lines exist from the start of the store; native u needs 20 bars; the retest/false_break memory M bars.
Data: level triggers need NO data outside the tape, but they need a minute-bar series (1-minute OHLCV incl. back-adjustment at rolls), the 15-minute and 5-minute pivot machinery, and for profile_nodes the volume-at-price of the prior day(s). In NT8 this means a secondary 1-minute series (plus tick-level volume-at-price) inside the strategy: heavy relative to a bars-only trigger but chart-free (BarsRequest / AddDataSeries). Ambiguity flagged: the level timing (T0 = previous bar close) and the 120 s staleness rule are engine behaviours that an NT8 coder would not guess; line lookups use the store as of its last rebuild (Nov 17), while the sample dates are Nov 9-11 (matched exactly).

### 3.8 trig_live_seven K7 (L9aa7805c, time_m_5) [th_swap/k7.py via trig_live_seven.py]
KB Keltner break exactly as the live DS7: ema = EMA(14) of close (alpha 2/15, seeded c[0]); ATR(10) Wilder-style atr = (atr*9 + TR)/10 seeded with the FIRST bar's TR = h-l; up = ema + 1.0*atr, dn = ema - 1.0*atr; BUY when c > up and the previous bar was not above its up; SELL when c < dn and the previous bar was not below its dn. Evaluated for every bar from bar 0 (first bar cannot signal). Parameters are the live defaults (ema 14, atr 10, mult 1.0) on a 5-minute bar (the live K7 bar is 3 minutes).

### 3.9 trig_pullback_ema (trend pullback) [triggers_b/impl_pb.py, core.py]
Books: L1edb9fab (tm300 depth len 10 w .5), L7c368a4f (time_m_5 depth len 10 w .5), Lfb608c7b (vsess_600 depth_native len 40 w 1.5; Asia stack), M3f6f752c (dib_3500 count len 10 n 2; long-only).
Series: o,h,l,c after the roll back-adjustment where the stored row has iid (not for tm rows). fast = EMA(len), slow = EMA(2*len). Native (depth_native, count_native): time-EMA over irregular bars, alpha_i = 1 - exp(-dt_i/tau) with dt_i = seconds between this bar's close and the previous bar's close (continuous series, includes overnight gaps) and tau = len*60 s (fast) and 2*len*60 s (slow), seeded with c[0]; len is CLOCK MINUTES (Lfb608c7b: 40 min and 80 min). ATR = Wilder (atr_i = (atr_{i-1}*13 + TR_i)/14, seeded with first TR) of the same series.
depth: state tu in {+1,-1,0} = trend up if fast > slow. On a trend change to up: sh = h, pl = l (swing high, lowest low since); mirror for down (sl = l, ph = h). Each bar in an up trend: LONG if (sh - pl) >= w*ATR[i-1] and c[i] > h[i-1]; afterwards if fired or h[i] > sh: sh = h[i], pl = l[i]; else if l[i] < pl: pl = l[i]. Down trend mirrored (SHORT if (ph - sl) >= w*ATR[i-1] and c[i] < l[i-1] and i >= 2; if fired or l[i] < sl: sl = l[i], ph = h[i]; else if h[i] > ph: ph = h[i]). Not an edge test: every qualifying bar fires.
count: LONG if fast > slow and the last N closes before bar i were each lower than their predecessor (cd >= N: N consecutive lower closes ending at i-1) and c[i] > h[i-1]; SHORT mirrored (cu >= N consecutive higher closes, c[i] < l[i-1]). Counters update after the test (cd = cd+1 if c[i] < c[i-1] else 0).
The state runs from the series start; bar 0 never signals. On a trend change the swing is re-initialised from the changing bar itself (sh = h[i], pl = l[i]) before the test on that same bar. Warm-up: EMA convergence (2*len bars; native 80 min of clock time) + ATR 14.
Data: bars only (native needs bar close times).

### 3.10 trig_structure_* [triggers_b/impl_lib.py, impl_st.py]
- libpattern threebar (L1756b913, tm240, filt 20): l3 = low two bars back. bull = l[i-1] < l[i-2] and c[i] > h[i-1] and c[i] > o[i]; bear = h[i-1] > h[i-2] and c[i] < l[i-1] and c[i] < o[i]; filt 20: bull also needs c[i] > EMA(20)(c), bear c[i] < EMA(20). Signal on every qualifying bar (not an edge).
- inside (M7423c0d9, time_m_3, k 1, filt 20; long-only id): mother bar m = i-k-1 (= i-2); every bar j in m+1..i-1 must satisfy h[j] < h[m] and l[j] > l[m]; then LONG if c[i] > h[m] and c[i] > EMA(20)(c) (or EMA undefined), SHORT if c[i] < l[m] and c[i] < EMA(20). The M-id keeps the long side.
- level round_break (Le9bd7276, drb_700, grid 50, buf 0.0): raw = c - roll-adjustment (raw price); a = ATR14 (Wilder first-TR seeded); LONG if raw >= floor(raw/50)*50 + buf*a and the previous raw close was not >= that same threshold (i.e. the close has moved from below a 50-point multiple to at/above it; with buf 0 any upward crossing of a multiple of 50, e.g. 24950 -> 25000); otherwise SHORT if raw <= ceil(raw/50)*50 - buf*a and the previous raw close was not <= that threshold (downward crossing of a multiple of 50). Long has priority if both. Not an edge flag, the previous-close test is the edge.

### 3.11 trig_trend_linreg thresh_native (L063a587d, bmsgq_B200, len 80, width 2.5) [th_grid/trig_trend_linreg.py + trend_common.py]
Native on activity bars: Leff = clip(round(len*60/ref), 2, 300), ref = median over bars 1..2000 of the seconds between consecutive bar closes (dts, floor 1e-3 s) = 50.851 s -> Leff(80) = 94. Slope = OLS slope per bar of the last Leff closes; vol unit = rolling population std (ddof 0) of the close difference over Lb = round(14*60/ref) = 17 bars (floor 1e-9); t = slope*Leff/vol. State: +1 if t >= 2.5, -1 if t <= -2.5, 0 (flat) otherwise (no hold). Event = bar where the state becomes +1 (resp. -1) from any other state. Not suppressed in the first 2000 bars (this module has no warm-up cut except the windows).
bmsgq_B200 = quote-message bars from the book feed (top of book mbp-10); the bars themselves need depth/quotes (see bar page). The trigger on top needs bars only.

### 3.12 trig_book_dwm dev_follow (L578701ed, time_m_1, L 200, z 2.0; Asia stack) [triggers_c/defs.py, featc.py, core.py]
Feature x = DWM deviation at the bar close: from the 10-level book snapshot (bid prices/sizes, ask prices/sizes), bid-side size-weighted average price bw = sum(bpx_k*bsz_k)/sum(bsz_k), ask-side aw likewise over the ask levels; DWM = (bw+aw)/2; mid = (best bid + best ask)/2; x = DWM - mid in ticks (+ = depth centre of mass above the mid). Taken from the last VALID book record (uncrossed, both sides non-empty) with receive time <= the bar's known_ts. The records are the 100-ms-final snapshots of the mbp-10 history (/mnt/l2/l2vast/_hist_replica, which includes Asia).
Signal ('z' mode, follow): sd = rolling sample std (ddof 1) of x over the last 200 bars including the current (min_periods = max(5, 200//3) = 66); y = x/sd (NaN if sd = 0); LONG level when y >= 2.0, SHORT level when y <= -2.0; event = edge (first bar where it becomes true); part==1 bars are dropped. 'follow' = trade in the direction of the reading (fade swaps the sides).
Data: LEVEL 2 DEPTH (10 levels sizes and prices) at the close of every 1-minute bar. NT8: needs OnMarketDepth with 10 levels from the feed; the engine used 100 ms grid; D8 would sample the book at the bar close. NOT a bars-only trigger. Ambiguity: price units are the int ticks of the grid arrays; x is in ticks; since y is normalised, units cancel. The feature store alignment demands stored known_ts == bar t_close, otherwise NaN.

### 3.13 trig_tape_unfinished unf_fade (L6547965c, swing_pct_8, m 6, cp 0.0; NY AM) [triggers_c/defs.py, featc.py]
Footprint of the bar's own prints (ts_event within [bar t0, bar t1]; side from the aggressor flag: buy aggressor = volume at the ASK, sell aggressor = volume at the BID; unknown side split half-half); only when the bar's price range is <= 400 ticks (else NaN, no signal). bv = sell-aggressor volume per price row, av = buy-aggressor volume. f_hi_bid = bv at the bar's HIGH row, f_hi_ask = av at the high row, f_lo_bid = bv at the LOW row, f_lo_ask = av at the low row. Unfinished high: f_hi_bid == 0 and f_hi_ask >= m (6); unfinished low: f_lo_ask == 0 and f_lo_bid >= m. 'follow' = LONG on unfinished high only, SHORT on unfinished low only (both true -> neither). unf_FADE swaps: SHORT on an unfinished high, LONG on an unfinished low. cp = 0 -> no close-position gate (cp > 0 would require close position <= cp for the high case). Event = edge. Data: TAPE with aggressor side per print (every print inside the bar) = tick-level data; swing bars (leg bars) so the high/low are the leg extremes. NT8: needs tick data with bid/ask classification (OnMarketData Last vs bid/ask) and a volume-at-price accumulator per bar.

## 6. Open items and honest ambiguities
1. Series-history dependence of native variants (section 4): hard-coded constants from 2023-04; a different chart start changes nothing only if the constants are fixed.
2. Level lookup timing (T0 = previous bar close, 120 s staleness) and the 1-minute store used to build lines (back-adjusted, rebuilt Nov 17) are engine behaviours; they reproduced all 12 level-trigger books exactly on the sample dates but an independent NT8 implementation has not been tested here.
3. Roll treatment is not uniform across modules (point 5 of section 1). The sample dates contain no contract roll; roll days are untested here.
4. The event files carry no position blocking (each signal has its own bracket); the stack layers apply blocking later. This page covers triggers only; fills, brackets, filters, windows are outside.
5. Early-close and holiday sessions were not sampled (Nov 9-11 are normal days). DST: the sample is after the 11-01 fall-back (EST), the spring change is untested.
6. 'M' ids and L05350e98 are long-only in the events file; the L-id raw module is two-sided. For D8 the side must come from the book spec, not the module.
7. Ldcdb0b6e etc. are labelled 'long' in the cell key (screen mode) but are BOTH SIDES as engine-run; this is confirmed here (events contain both signs and match both-side raw signals).
8. I did not independently re-implement the triggers outside the engine code; the test vectors are the engine's own modules on the engine's own stored bars. An NT8 port must be checked against these CSVs signal by signal.
