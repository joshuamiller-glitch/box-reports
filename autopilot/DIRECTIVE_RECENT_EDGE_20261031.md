# T-RECENT-EDGE — user directive pasted 2026-10-31 (verbatim)

T-RECENT-EDGE — the standing program for "what works NOW": find it, size it, track it, and know when it stops (2026-10-31)

Research only. Same rules as PLAN36 (measured + live-cal fills; per contract first; session column; QUANT-LAYER; prereg per cycle; dead cells; placebos). This program is STANDING: it runs every night after the data window moves (and every 4 h while the other programs run), it owns RECENT_WINS.md, and it answers one question in three parts — what is working in the most recent months, is it real enough to run, and is it still working.

0. Why this is its own program
The user trades the market as it is now. Every program this week found rules that are strong in the last 3-6 months and flat or negative in 2023-24 (trend terciles, first-stop cut, skip-after-loser, session-open drift, the 11-line set). The standing gates treat those as "not forward-consistent" and stop. That is the right answer to "is this a permanent law"; it is not an answer to "should I run it this month". This program answers the second question properly — with the discipline that makes a recent edge usable: how recent edges have behaved historically (do they persist?), how to size them, and how to detect when they stop.

1. The RECENT-EDGE ledger (RECENT_WINS.md becomes this; rewritten every 2 h; it is the user's page)
Every rule from every program that is positive in L3M AND L6M on the primary measure (per contract and stack), de-duplicated, with the QUANT columns, PLUS the new columns this program adds:
PERSISTENCE SCORE: from section 2 — the historical probability that a rule with this profile (positive L3M + L6M, this magnitude, this fire rate, this family) stays positive over the NEXT 3 months.
AGE: how many consecutive months the rule has been positive (its streak), and the month it turned on.
HALF-LIFE estimate for its family (section 2).
DRIFT: the rolling 1-month per-contract number for each of the last 6 months (a sparkline in numbers) — is it rising, flat, fading.
REGIME TAG: which day-vol tercile / session / trend state carries the gain (so a regime change is visible).
SIZE RECOMMENDATION: from section 3 — the fraction of normal size a recent-only rule should run at given its persistence score and MDE.
STATUS: NEW (first month), RISING, STABLE, FADING, STOPPED (section 4), with the date of the last status change.
IMPLEMENTED?: whether it is in D6 (group / property / value) or in THP_POLICY.txt, in shadow, or neither.
Header: the top 10 by L3M $ at live lots × persistence score; the count by status; the sentence "this month the edges that turned ON are …, the ones that FADED are …, the ones that STOPPED are …".

2. Do recent edges persist? (the meta-study — run once, refresh monthly)
Take every rule the box has ever scored with a monthly series (the DEAD_CELLS and UF_TRIALS ledgers carry ~2.5 million cells; sample 50,000 stratified by family). For every month M from 2023-10 to 2025-11: the set of rules positive in the 3 months before M (and in the 6 months before M); their mean per-contract result in the 3 months AFTER M; the share still positive; the same by family (entry filter / entry structure / confirmation / exit / sizing / stack / regime), by magnitude bucket, by fire rate, by whether PRE was also positive, by whether the placebo was beaten. Deliver: (a) the persistence curve (P(still positive next 3 m | positive last 3 m) overall and per family), (b) the decay: how the edge's magnitude falls from month +1 to +6 after selection (the half-life per family), (c) the shrinkage factor: the ratio of out-of-sample to in-sample magnitude per family (this is what a recent edge is really worth), (d) which signals of persistence exist (streak length, placebo rank, PRE sign, fire rate, stack correlation), as a small model: P(persist) = f(features), walk-forward across months, calibration curve. Report DS3_PERSISTENCE.md; its outputs feed the PERSISTENCE SCORE and SHRINKAGE columns above. Plain sentences: "a confirmation rule positive in the last 3 and 6 months stays positive in the next 3 months X % of the time and keeps Y % of its magnitude"; "a sizing rule …"; "the best predictor of persistence is …".

3. How to run a recent edge (sizing and portfolio)
For the rules in the ledger with persistence score ≥ p (p = 0.5 / 0.6 / 0.7): (a) the shrunk expectation (in-sample × shrinkage factor) and the Kelly-fraction size at that expectation and the measured variance, capped at 1.0 × normal; (b) the portfolio of recent edges run together on the stack (the lock engine) — mean, SD, maxDD, worst-20-weeks in L3M / L6M, with the correlation between the edges (many "recent" edges are the same regime wearing different clothes: say which); (c) the equal-risk frame; (d) the rule "run recent edges at the shrunk size, re-evaluated monthly, dropped at STOPPED" scored as a WALK-FORWARD policy across 2024-2026: each month, run the ledger's edges as of that month at the recommended size, measure the next month; vs doing nothing and vs running everything positive at full size. This is the honest test of the user's approach. Report DS3_RECENT_PORTFOLIO.md: "running the month's recent edges at shrunk size would have made X $/wk over 2024-26 (MDE Y), Z of W months positive; running them at full size … ; the drawdown when a regime ends was …".

4. When does it stop? (the monitor)
For every rule in the ledger, from its monthly series: a CUSUM on the per-contract stream with the alarm threshold set from its own PRE variance; the rolling 20-trade / 4-week mean vs its L6M mean with a z-score; the regime check (is the day-vol / session mix that carried it still present this month); the rule's status transitions (NEW → RISING → STABLE → FADING → STOPPED) with the dates; back-tested on 2024-26: how many weeks after an edge actually died did each monitor flag it (the lag), and how often it flagged a live edge falsely. Report DS3_EDGE_MONITOR.md and the STATUS column; plain sentence "the monitor would have flagged the end of the X edge Y weeks after it stopped, with Z false alarms a year".

5. Expand the search for recent edges (new cycles, the families the gates buried)
Everything that was positive in L3M + L6M but failed the all-window gate this week is re-examined under THIS program's lens (persistence score, shrinkage, size), not killed: the trend terciles (EINT1), skip-after-loser (N1 b), skip-first-60-min (N1 c), the first-stop cut pooled (S2), the 11-line set (Z2), the KB 2-m HA (C2), the HM 15-s (C2), the 70% take / tighten families on the N basis in L3M only, the sub-minute MA events with L3M > 0, the bar-type cells with L3M > 0 (the 6,943 BARS-CAND rows), EINT2's day-type rules, the ensemble subsets positive in L6M/HOLD. Each gets: the monthly series since 2023, the persistence score, the shrunk expectation, the status, and the one-line "run at X % size / shadow / no". Then NEW cycles aimed at the recent regime specifically: (a) rules fitted ONLY on the last 6 months with a 1-month forward test rolled through 2024-26 (the pure recent-fit chain) for every family; (b) the regime description of 2025-26 itself (what is different: vol, trend persistence, session shares, book depth, ES correlation) so the user knows WHAT he is betting on when he runs a recent edge; (c) the "regime library": the same edges scored in every prior 6-month regime of 2023-26, so each edge carries the list of regimes it worked in.
