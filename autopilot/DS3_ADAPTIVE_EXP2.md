## 3. Part (d) joint stack policy on the exact lock engine
Engine and conventions: dvg_lib / sl_lib per-book 1-s lock engine for ST HM WT KB SM PE (frozen stack weights, day entry test, give-back arm, week floor, sweep cost); weekly stack $ in engine report scale. A modified trade replaces its engine row (P = M + 0.742 so that the engine's own 0.5 pt slip and fee reproduce measured M; TH stream pts + 0.5), exit sample = ds2_SS sample of the exit second, size multiplier round(NOM*60/stop)/NOM, and the book stays single-position (a row whose entry is before the previous kept row's exit is blocked; entries the baseline blocked cannot be added back: a conservative-for-activity simplification). Rows that can be modified (engine rows to 2026-02-06 matched to an ABR entry): ST 86%, HM 90%, WT 91%, KB 83%, SM 95%, PE 96%. Sections consistent on the same trade: exit = earliest of bracket exit, profit-stream exit, loss-stream exit; a TH decision applies only if it precedes the bracket exit; the streams exist only while the 60/60 live trade would be open, so the TH layer is inactive after that (disclosed). ## 7. Caveats, deviations, disclosures
* **UNTOUCHED slip (self-reported, DECISIONS)**: vs_lib.WINS['HOLD'] has no upper bound (engine day axis runs to 2026-10). The first part-(d) final run therefore aggregated HOLD / WF-all weekly statistics over label days after 2026-02-06 and printed them once. Those numbers were discarded (renamed DISCARD_joint_*_uncapped_hold.json, not used), the code now caps HOLD at 20260206, the run was repeated and all numbers in this report are from the capped run (HOLD 32 weeks). PRE and X' were unaffected; parts (b) and (f) use the capped ABRC2 spans. The same code is used by the engine baseline of other agents (vs_lib): their HOLD windows should be checked.
* Prereg: part (f) count 24 not 28 (errata); stop 150 not scorable from the store; EXP1 streams not in schema; the PRE-only file for (d, f) was written after the (d) PRE table, before any HOLD/X' of d or f was read.
* The trade-level (b) numbers ignore the single-position busy chain and the locks; part (d) is the stack-level check. Entries the baseline blocked (book busy) that a faster exit would free are not in the store, so the engine understates policies that exit earlier; for wide no-time-exit brackets the bias is the other way.
* Engine rows not matched to an ABR entry (4-17% by book) keep their native brackets; the regenerated live rows differ from the library rows used by ABRA for 13-21% of ABR entries (unmatched ABR entries are not in the live stack).
* Lots: parity lots use the book's live lot average (KB 5.2, SM 7.4, PE 5.6 from ABRC2); engine runs use nominal lots with the frozen stack weights.
* Slippage: the 10-lot walk estimator is conservative for fewer lots; a MRP sensitivity was not repeated at the cell level.
