# NOTE FOR THE USER: exit-before-add-fill ordering (research engine bug; question about live D7) - BASE-4, 2026-11-02

**What the research engine did (d7lib._compose_d7, used by D7 v1.0d..v1.3 / V13X):** a position is entered as 70% at the signal plus a resting 30% limit (the dip-3 add of the 70/30 split on every book, or the OTE-62 B73 add that rests behind the POI level). When a TH-L2 loss cut or a profit take line fired at second kx, the engine applied the exit only if kx came AFTER the second the 30% limit would have filled. If the exit came BEFORE the fill, the exit was silently ignored: the 70% kept running to its original stop/target outcome and the 30% still filled later (after the exit time) and rode to the target. Counted on the library: 846 rows (145 OTE-62 B73 rows + 701 dip-3 split rows); 125 of them TH-L2 loss cuts, 721 take-line exits.

**What the live code must do (and what V13Y now models):** an exit of the 70% leg (loss cut, take line, tighten breach, any lock flatten) cancels the resting 30% limit in the same step. The add never fills; the exit applies to the 70% only. (V13Y: net = 0.7 x full-position points from the original entry, then the exit delta on 0.7 lots.) The same rule should hold for the per-book locks and the stack lock when they flatten.

**Question to answer from the live code (D7 / D6):** when the TH-L2 loss cut or a profit take fires while the 30% limit is still working, is that limit cancelled? If it is NOT cancelled, the live book can fill the 30% after the exit and hold an unintended position (with the original bracket) after the cut; that is the dollar-negative orphan the engine's old behaviour mimicked in the other direction. Please check (a) the TH-L2 cut path, (b) the profit take / tighten path, (c) the day / week flatten paths, for an explicit cancel of the pending add, on both the dip-3 split and the OTE-62 B73 add.

Effect in the research numbers (D7 V13Y vs V13X, lock none, five take lines ON): F9 mean +3.1k/wk, maxDD 132.6k -> 96.2k; PRE 178k -> 130k; X' 135k -> 70k; the take lines, which looked harmful on V13X, now cut maxDD in every window at a mean cost (autopilot/DS3_V13Y_BASE.md).
