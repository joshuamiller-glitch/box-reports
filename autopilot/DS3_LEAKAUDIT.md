# DS3_LEAKAUDIT - day-level look-ahead audit of the DS3 program (LEAKAUDIT, 2026-10-30)

Scope: every program that used a day-level regime/vol tag or any feature computed from the same trading day's later data as a gate, table key, feature, stratifier or scope for trades that begin before the information is known. READ-ONLY: no report rescored, no file edited or deleted (except the two new files and the DECISIONS/MORNING appends), no execution, no outcome data after 2026-02-06 opened (only code, stored report text, aggregate tables and the day-level day_regime / day_labels / event-calendar tables). Companion: autopilot/DS3_CAUSAL_TIMES.md (availability time of every day-level feature, causal recipe).

## 0. Bottom line
1. The UF-LOSS finding is CONFIRMED and is wider than UF-LOSS: the same column (`vol_tag_entry_day` = `vol_tag_today`) keys the EXP1 PROFIT side. The EXP1 3x3 vol x session chains (3 profit CANDIDATE), the fixed-cell table, the published 8-rule table (policy_candidate_exp1.txt) and the post-look LEAD "vol_lo+ON take at 50% of target" (PRE +4.27, HOLD +3.52, X' +2.97) all use the look-ahead key for the ON half of their trades (53% of trades). They must be treated as VOID until re-run with the causal key. The EXP1 loss side is causal (exp1_loss.py:41). The statement in UF-LOSS C3 amendment A1 "corrected gate ... as EXP1 did" is true for EXP1-loss only.
2. What the column is: the OVERNIGHT range (18:00-09:29) of the label day vs its prior-20-day median (thp_dayreg.py:41-45), complete at 09:30:00 ET; not the regular session. For ASIA entries 48-100% of the summarised window is still in the future at entry, for LONDON 6-48%, for PRE the entry hour itself is inside it; the trade's own MFE/MAE path is part of the tag, so the leak is outcome-correlated. Persistence check (day-level only): prev tag == today tag on 42.3% of 737 days, so a causal key re-assigns ~58% of days.
3. Everything else that carries a day-level key is either causal (checked in code) or affected only in descriptive/regime-split tables whose pooled verdicts do not depend on them (section 2).
4. The THP/ABR leak_test (346 cuts, 0 mismatches) cannot see this class of defect: it noises bar data after the cut but loads day_regime.parquet unchanged.

## 3. Not audited / limits
* Pre-DS3 autopilot batches (outputs/autopilot/REPORT_*: K, Q, RZ, SW, BI series) were not read line by line. DECISIONS text shows: Q18 look-ahead already found and fixed; RZ5 used realised range only as a descriptive tercile; BI4 (high-volume-day premium) and K100 (first-30-min volume skip) are verdict NO, so a day-level leak could only inflate; nothing to act on unless one is revived.
* failpred, pairP, forward/live code and the box scripts were out of scope. The individual per-cell SESSION2 reports were checked through their shared builders (above), not one by one.
* "Causal" here means no day-level value from a later time reaches a trade/decision; it is a code reading, not a re-simulation. Ex-ante forecasters (P_quiet) carry their own in-sample-fit caveat (first fit window 2023-03..06), which is a different issue.
