## THP_POLICY / D6 mapping

Written as a COMMENTED line at the end of THP_POLICY.txt (NEEDS: D6 does not compute volSpike3Against = last completed 1-minute bar range > 3 x the median of the last 60 one-minute ranges and the bar closes against the trade; sameSideBookStopped = another D6 book on the same side has been stopped while this trade is open; mae = the trade's running maximum adverse excursion). Nothing is live-readable. Features named in DS3_THL2_NEEDS.md (section RISK-OFF).

## Gaps and caveats
* The stop move is simulated on the signal's library path and applied to the composite rows; the 45-s PE confirmation entry and the 70/30 add leg are handled as described in DS3_RISK_OFF_A.md section 1 (whole position at the new stop; the add never fills if the stop is touched first). A live D6 stop modification has its own latency and replace risk not modelled (the 1-s latency to the next second only).
* Destinations not built: FVG/OB edge, POC, absorption price, VWAP band. Triggers not built: stack at -X R by second, first book to +X R (only same-side stop / target events), intraday VIX, ICT silver-bullet calendar. Stack-line HM/PE: the library entry is used for the trigger path (RO-2's caveat applies).
* The shuffled-day control is implemented as a timing permutation among touched trades of the same book x session; calendar-shifted triggers were not run.
* Multiplicity: the 483,488 NTE-2 cells are all counted (UF_TRIALS per_program RISKOFF_NTE2; DEAD_CELLS +483,488 rows); variants added after the first look: learned fit v0 -> weighted w (counted), the named KB example (counted).
* Questions for the lead: none that block. (For the record: the candidate above should only enter the forward register if the user wants any stop-modification experiment at all; the evidence is a small positive inside noise.)
