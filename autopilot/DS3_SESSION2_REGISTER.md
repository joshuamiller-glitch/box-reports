## Record format (same as D3CFC)
Source JSON in l2vast/struct48/paper_all/<id>.json (fields cell_id, object, verdict, params, backtest_expectation, caveat, forward, source, expect_mean_wk, expect_sd_wk, date) picked up by `ap_forward_register.py watch` into series/PAPERALL_CELLS.json (sha256-frozen). Each record's params carry: session + window ET, session_tier, basis (mapped / direct / mapped+direct / "rows-as-stored" = ledger gave no basis label, stored fills, read as mapped), best_of_F_label, slippage_breakeven_pts (+src), source rows path, cluster, live_change NONE. Pairs also carry both legs (cell, family, session, window, rows, basis, pooled label), per-leg break-even and HOLD at +200/+400/+800 per-trade stress.
- Singles: expect_mean_wk = HOLD mean/trade x HOLD trades/wk at the stored 10 lots (the lot sizing "0.5 x" of SESSION_REGISTER is carried as a sizing hint in params, NOT applied to the expectation); expect_sd_wk = PRE weekly SD (zero-filled over 75 PRE weeks, entry-session trades only). Break-even: ss3 stress.csv where the cell is a stress single (S01 etc.), otherwise derived = min(PRE, HOLD) net mean per trade / $200 per pt (10 lots, $4.84 RT already netted); both PRE and HOLD derived values are stored.
- Pairs: expect_mean_wk = HOLD $/wk of the half-size row, SD = HOLD SE x sqrt(32 wk); break-even = stress.csv breakeven_pts (2.05..3.09 pts per trade). Examples: P08 half +15.9k/wk (BE 2.40 pts), P28 half +12.7k/wk (BE 2.92).
- Expectations are selection-inflated; MDE, 2023 span, HOLD are inside backtest_expectation. Start week 2026-W45 comes from a new optional `start_week` field in the record (see code change); existing records unaffected.

## Feed status per engine (evaluator can/cannot produce forward rows)
The evaluator's script feeds are: ds3_TE_ bar books (ap_ds3_shadow: st/kelt/emax), STRUCT48 sleeves, T14, DS3/DS5 live files. NONE of the source engines of the 107 records has a forward row generator: ICT-IC (34 reps + 8 of the pair legs), ICT-SF/CRT (9 reps + the PASS cell), T-PB pullback/PBX (12), T-ENTRY pb4/TB4 (7), H4 (5), T-TREND TR1 (4), BA bracket-assign rows/rows2/rows3 (9), T4-G2 (3), T-ENTRY e1 (3), T-BRACKET (2), T-PRO1/2/3 (3), SB (1), TSO ST10 (1), D4a (1), pair legs IC+SF/PRO/e1/d4a, and WT block. All 107 therefore carry shadow kind `pending_feed`; status "ENTRY-ONLY / PENDING-FEED (<engine>)"; no rows fabricated; realised/z/verdict shown n/a (never zero, no PROMOTE/RETIRE possible). The stored-fill rows are not a forward source (they end 2026-02-06). Closest to a feed: x_crt.py replays CRT_H4_M5_close only (not M15_M1_close_ib); the WT block could be fed from live WT rows entered 12:00-15:00 ET (needs a small script, not built, since the block would then score at live lots not the stack-exact expectation). Building generators = DIRECTIVE_SESSION2 item A/B work (live-latency 1-s replay of the survivors on forward weeks).

## How to read it
FORWARD_REGISTER.md "Registered cells": columns evaluator/verdict show ENTRY-ONLY / PENDING-FEED, weeks live 0, expected $ per week = the frozen expect_mean_wk. When a generator exists, add `shadow` {kind:"script",...} to the frozen record (or remove + re-register) and the same table starts scoring from 2026-W45 with the usual rule (PROMOTE >=6 wks z>=-1, RETIRE >=8 wks z<-2). The WATCH row never promotes.
