## What was done
- Engine l2vast/ds3/code/tb_lib.py (+ tb_cells.py, tb_run.py, tb_pipe.py, tb_daily.py for prereg 10, tb_final.py). NQ 1-min continuous tape (roll back-adjusted, 2022-06..2026-10-16, same label-day axis as Set A/DS2: 953 days from 2023-02-10) aggregated to 1, 2, 3, 5, 15-min bars; daily and weekly bars for P10. Look-ahead truncation test (tb_test.py): 0 mismatches across 16 signal families at 3- and 15-min.
- Live cost: market entry/exit next bar open -/+ 0.995 pt, stop exit stop -/+ 1.01 pt (gap: open), forced flat 16:55 ET, $4.84/lot RT; one position; entries 18:05-14:59 ET. Stops/targets tested on the k-min bar high/low (stop first). The 1-s intrabar path is not simulated (1-min tape = NT8 chart data).
- Sizing: lots = 12,000 / (nominal stop x $20) so R = 12,000 = ST10's R (10 lots x 60 pt). Per-book locks (day -2R/+5R, give-back arm 2R keep 50%, week floor 12R, cap off) applied at **closed-trade level, an approximation of the exact engine** (exact engine not run; see caveats). P10 (daily/weekly) has no intraday locks.
- Monthly WF re-fit inside the window: per cell a 3-9 point grid declared in the prereg; each month the grid point with the best trailing-6-month net $ (trades closed before the month, >= 20 trades, else the centre point) trades that month.
- Benchmarks per cell: ST10 alone, HM10 alone and the pair ST10+HM10 (DS2_daily pnl_ST/pnl_HM, 10 lots, per-book locks), same windows. Marginal Sharpe = pair (or ST/HM) vs benchmark + cell scaled to 0.5 x its weekly SD. Weekly corr to each. Equal-SD weekly difference vs ST10 and HM10 with bootstrap CI (eqsd_diff_*).
- Placebo of record: 100 timing-destroyed draws (raw signal state of every grid point circularly shifted by a random offset; price decoupled; filter, exits, re-fit and locks identical), rank of the cell's WF mean. Second null: 200 random-entry draws (same label day, random side, same holds/exits), `placebo_rank_rand_WF`. Note both nulls bear the full cost drag, so a rank near 1.0 only says the cell beats cost-bearing random timing; it does not say the cell is profitable (e.g. 1-min cells with WF mean -$30k/wk still rank 1.0). The mean-up and holdout conditions carry that.
- Library pool (l2vast/ds3/out/pool.parquet) percentile: the NQ intraday library holds 11,750 NQ series (many 5-min trend families, e.g. V5P1 MACD/ST/MA-cross variants); I report each top-20 cell's holdout Sharpe percentile among NQ intraday pool series (0.65-0.84). I did not de-duplicate rules against pool names; the T-B cells use their own parameter grids and the live cost model, so equality with a pool series is not implied.

## Caveats (decision-relevant)
1. Locks are a closed-trade approximation: day/give-back/week-floor decisions are taken on realised trade P&L, not the mid-trade 1-s path used by the exact engine. For several cells (all Renko, k=1 cells) locked and unlocked results differ by tens of $k/wk, so cell verdicts there are provisional until run through asm_lib/riskeng with the exact engine. Unlocked WF means are given in the table for the CANDIDATEs.
2. Stop/target order inside a k-min bar is resolved stop-first; entry-bar targets are disallowed (conservative). Fill model does not simulate queue position on stop-joins.
3. `neighbours_agree` here = >= 2/3 of the fixed-parameter grid points share the sign of the cell's WF mean and holdout mean; not an adjacent-cell test across bar sizes.
4. 2x-cost sign is approximate (extra 1 RT of ~2.0 pt + $4.84 per lot per trade), not an exact re-run.
5. Tick / volume bars: not built (no per-trade tick-bar table was used; data/ticks holds 1-s style daily npz and bars2 holds 1-min/1-s aggregates with trade counts only). 500/1000-tick and 1000-volume bar results are therefore not reported; the 1-min bar volume proxy is used only in P8.
6. The 2023-04..2024-01 span is partly in-sample for the monthly re-fit warm-up (first fit month 2023-02 uses 2022-06 onward); `span23_mean` is the series mean over those days, logged with the pre-holdout look (the span is part of the IS window, not the holdout).
7. Holdout looks: one per prereg, tracks DS3_TB_P1..P10, pre-holdout texts autopilot/DS3_TB_P<n>_PREHOLD.md logged with sha256 in ledger/holdout_looks.jsonl before the holdout was scored (each prereg's cells were all computed together; selection after the look was not used to change any cell).
