## 1. What was built (l2vast/ds3/code/thl_hm/)
| file | job |
|---|---|
| fwd_score.py | scorer: HM rows of the NT8 trade logs -> per trade HOLD (60/60/16:55 bracket) and RULE (nine L6 cells) arms on the 1-s path with the THL B kernel and MEASURED fills, LIVE arm from the log, paired deltas, flags, week-block bootstrap, A1 status, weekly running count. Hard date floor 20261101, sealed span only tallied. |
| fwd_marks.py | writes autopilot/DS3_THL_HM_FWD.md (template state now: `--init`); freezes the exact first-500 and first-1,000 snapshots when reached; one primary row, 8 DESCRIPTIVE rows; expected dates. |
| fwd_path_build.py | builds the forward 1-s path from ticks (NT8 tick CSV or a Databento trades file) in the tables/NQ/1s layout, into its own directory. Refuses input before 2026-11-01 UTC. |
| fwd_score_test.py | dry run on SEEN data only (test flag lives only in this file; the CLI has none). 21 checks, all PASS (section 4). |

The A1 statistic is d_sim = RULE minus HOLD per trade (pts, basis M), both re-simulated from the live entry, exactly the prereg definition. d_live = LIVE minus HOLD (as traded) is printed beside it for transparency but is execution-confounded and does not drive the status. Reason both exist: the live rule is ON, so the logged exit of a cut trade is the cut, and the hold-to-stop outcome can only come from the path. Status (Amendment A1): INCONCLUSIVE below 1,000 HM trades, always; at >= 1,000 the scorer computes the section 5 fresh-look rule (CONFIRMED-FRESH needs M mean > 0 with week-block CI lower bound > 0, C mean > 0, >= 7 of 9 cells positive; primary mean <= 0 is DEAD; otherwise INCONCLUSIVE). The scorer only computes it; taking the look (THLHM_FRESH in holdout_looks.jsonl) is the lead's act.

## 3. The 1-s path: what exists, what is needed
Found (names only; contents not read): /mnt/l2/l2vast/tables/NQ/1s/YYYY-MM.parquet exists for 2023-02 .. 2026-09, plus 2026-10.parquet and 2026-10__ext_20261012_20261018 / __ext_20261019_20261023. So a 1-s NQ table does exist past 2026-02-06 (sealed span, not to be read), built from the L2 pipeline, and it carries trd_px_hi / trd_px_lo / trd_px_last / trd_n / instr per second (ts = END of the second in ns; verified on a seen day: sec_start = ts/1e9 - 1 matches the bars2 seconds at 99.9%). The statement "no 1-s path after 2026-02-06 on this box" holds for the research arrays (SS/SH/SL/SC end 2026-02-06), not for this table.
Needed for the forward weeks: for every second with a print from Sunday 2026-11-01 18:00 ET to the last forward trade's 16:55 ET flat: NQ front-month OUTRIGHT high, low and last trade price (and print count to pick the front contract). Trades-derived only; **mbp-10 is not needed** for this test, nor quotes. Raw (unadjusted) prices are right: the live entry price is raw.
Ways to get it (all outside this task; any purchase needs the user's OK and none is authorised now):
* (a) The lead's L2 extension planned for Saturday 2026-10-31 06:40Z covers data up to that date; it does not cover November. Whatever job extends tables/NQ/1s weekly (the 2026-10__ext_* pattern) must keep doing so for 2026-11 and later (files 2026-11.parquet / 2026-11__ext_*.parquet); the scorer reads exactly that layout with `--path-kind table --path-root /mnt/l2/l2vast/tables/NQ/1s/` and opens only months >= 2026-11.
* (b) The weekly Databento pulls already in data/ext_YYYYMMDD/ (NQ_trades_<from>_<to>.dbn.zst, plus ohlcv1m and mbp-10 under /mnt/l2/l2vast/raw/NQ/ext). The trades file alone is enough: `python3 fwd_path_build.py --dbn <file> --out outputs/l2vast/ds3/out/thl_hm_fwd/path/ --tag <date>` then `--path-root` that directory. Cheapest purchase if the weekly pull is not already in place: the Databento trades schema for NQ only (no mbp-10).
* (c) An NT8 tick recorder or a Market Replay tick export (time, price, size) on the NT8 machine, pushed next to the trade logs: `fwd_path_build.py --csv ticks.csv --tz America/New_York`. Not found on this box; would have to be set up by the user.
Completeness rule: a trade whose day has no path, or whose path ends more than 10 minutes before the 16:55 flat (other than a CME early close or special closure, which is flagged early_end), is NOT scored and is counted in no_path. If no_path is not 0 the mark is not valid until the feed is repaired; the mark snapshot is frozen at the first run that reaches N, so repair the feed before the run that crosses 500 and 1,000.

## 6. Running it weekly (user or lead; nothing is scheduled by this task)
Each Monday after the Sunday-evening session data are in (trade csv pushed and the 1-s table or tick file for the week available):
```
cd l2vast/ds3/code/thl_hm
# 1) only if path comes from ticks / a Databento trades file:
python3 fwd_path_build.py --dbn <repo>/data/ext_<date>/NQ_trades_<from>_<to>.dbn.zst --tag <date>      # then use --path-root .../out/thl_hm_fwd/path/
# 2) score (running view; prints n, no-path, refused counts, A1 status, primary mean and CI, as-traded check)
python3 fwd_score.py --trades <repo>/data/live/StratTrades_DualStrat2_<acct>.csv <repo>/data/live/StratTrades_DS3_<acct>.csv ... --path-kind table --path-root /mnt/l2/l2vast/tables/NQ/1s/
# 3) regenerate the report (also freezes the 500 / 1,000 snapshot when reached)
python3 fwd_marks.py --trades <same list> --path-kind table --path-root <same root>
```
Outputs: l2vast/ds3/out/thl_hm_fwd/{fwd,running}_trades_scored.csv (per trade: deltas, flags, fired), *_weekly.csv (week, trades, cumulative count, weekly and cumulative primary mean), *_summary.json, mark500_/mark1000_summary.json (frozen), and autopilot/DS3_THL_HM_FWD.md. Memory under 2 GB, runtime under a minute for 1,000 trades; idempotent. It can be added to ap_live_arrival.py's chain by the owner (not done here: no live or arrival file was edited). Weekly numbers are descriptive; do not act on them before the 1,000 mark.
Checks on the first run: tally.hm_strategies lists the expected strategy name(s); files/redacted tags show where the trades came from; no_path = 0; spec_warn = False; fired agreement (live LossExit vs model fired) is high (a low value means the model rule differs from the live ManageLoss, covered by basis C and the as-traded line).
