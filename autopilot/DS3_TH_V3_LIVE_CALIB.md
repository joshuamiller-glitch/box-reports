## 9. Reconciliation: BASE-4's I1-preview N1 engine cuts versus this trigger table (CHAR-C's 16 of 99)
Code l2vast/ds3/code/v2/recon.py (map d-row -> tidx_cut position via the all_ea tree; default rule arm 30 / MULT 30 / 5 s / N 1; engine file /mnt/l2/l2vast/ds3_base4/defects/v2/week_i1_N1.pkl). Result: **99 of 99 engine cuts have a trigger row in this table**; engine exit_ts minus my decision second T: +1 on 83, 0 on 8, -1 on 1, +2 on 6, +5 on 1 (**16 of 99 differ from the +1 of the spec**, as CHAR-C found). All 99 trades have entry_ts equal to the library entry (no entry-time shift), so an entry-shift effect is excluded; values of upnl, p5 and med are identical on every second present in both tables. The 16 split into two causes, both in the engine-side preview, not in this table:
* **9 of 16 (exit -1 or 0): the fill second is not printed.** BASE-4's harness maps the fill second F = T+1 to the LAST PRINTED second <= F (searchsorted(SS, F, 'right') - 1, engine_v3_run.py line 49). In all 9 the second T+1 has no print (8 cases; in the ninth the decision second T itself has none), so the engine exits at T (or earlier), with the older print, instead of T+1. This is a path-index limitation (the engine path SS contains only seconds with prints), not a trigger difference; the spec's fill model (print of the fill second, forward-filled) gives T+1.
* **7 of 16 (exit +2 or +5): the preview K table dropped the decision row.** In all 7 my first qualifying second T lies on the epoch 10-s grid (T % 10 == 0): the stored K row exists there with identical values (upnl, p5, med), but the preview's trigger-row file (k1s_week_all_ea.parquet) holds only the NEW 1-s rows, excluding grid seconds already in the stored table, and the harness REPLACES the stored rows of the covered trades; the grid-second row is therefore missing from the table the engine fires on, and the engine fires at the next qualifying non-grid second (+2 s, +5 s). The preview's file has 334,136 rows against 574,904 rows of this table for the same 619 trades (333,490 identical keys; 85% of the other rows are seconds without a print in the engine path, the rest are the grid rows).
**Which is right:** the table here follows the spec (every second, forward-filled price, grid seconds included); a trigger table for engine use must contain the grid seconds (the stored rows) and the non-print seconds are not representable in the SS-indexed path (fill at the last printed second <= T+1, which is the closest the engine can come). Count logged: 16 of 99 differ (9 print-mapping, 7 missing grid rows); 83 of 99 exit at T+1 exactly as specified. The blind-span full per-second table delivered to BASE-4 (series_span_all_ea.parquet) contains every second.
