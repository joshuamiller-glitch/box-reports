## 2. Construction A (code/th_t2b: p1_parse, p2_snap, p3_run, p4_feat)
snap(t) uses only data available at t: OI published <= t (stat 9 comes out ~21:47 ET and ~10:00 ET), settlement <= t (settles >= 3.5 h old), option 1-min closes/volume <= t, NQ state mid. Black-76 implied vol per option from the settlement price; forward from put-call parity at settlement; trade-price mapping level = strike + (NQ mid at 16:00 ET - parity forward) so the futures calendar basis is removed. Intraday refresh: option trades in the last 60 min re-price the vol (per-option where traded, bucket ratio elsewhere); F follows the NQ mid.
Levels (MenthorQ names): call resistance = strike >= F with max call gamma$; put support = strike <= F with max put gamma$; the same for options expiring before the next 16:30 ET (0DTE: call/put/flip); gamma flip / high-vol level = zero crossing of total gamma$ over F+-10% nearest F (NaN when none: net gamma negative everywhere in that band, common); net gamma$ at F and sign; 1-day expected move = F x ATM IV (front expiry >= 1 day) x sqrt(1/252), anchored at the last 16:00 ET mid -> min/max edges, em_frac = side x (px - anchor)/EM, em_room (points to the edge in the trade direction). Two sources as UW does: 'oi' (open interest) and 'vol' (cumulative option volume since 18:00 ET). Three refresh policies: d = daily (22:00 ET prior evening, fresh OI), h = hourly, m = per-minute (full re-snapshot at the last completed minute of each decision). Coverage on JN05W2 decisions 69-76% (the rest: no usable option set that minute); 0DTE levels exist on 34%.
Check: the per-minute grid em_frac used for the exact gate vs the trade-table feature: corr 0.9993 (max abs diff 1.7 EM-fractions on the worst row).

## 4. Stability: is an hourly refresh enough? (A, JN05W2 decisions, 2024-10..2026-10)
| level (oi source) | hourly vs per-minute: share of decisions where the level differs > 25 / > 50 pts | daily(22:00) vs per-minute > 25 / > 50 |
|---|---|---|
| call wall | 8.5% / 8.1% | 24.5% / 23.7% |
| put wall | 8.8% / 8.3% | 25.2% / 24.4% |
| gamma flip | 14% / 6.3% (median shift 5 pts) | 49.8% / 35.6% (median shift 25 pts) |
| net-gamma sign disagrees | 1.3% | 5.7% |
vol-source (volume-built) levels are far less stable: hourly vs minute flip moves > 25 pts in 48% of decisions, walls ~20%; daily vs minute 78-88%. Reading: for the OI source an hourly refresh is enough (walls stay put intraday; the flip and the net-gamma sign move a few points); a once-a-day file (the existing NT8 file design) misses a quarter of the walls and half of the flips after the day's volume/OI/price change. Volume-source levels need minute updates. In the screens (section 5) hourly, daily and per-minute policies rank alike; none is clearly better, so refresh frequency is not the binding variable.

## 7. Would MenthorQ's NinjaTrader feed be an adequate live source? (public docs only, nothing bought; prices quoted)
- Mechanism (menthorq.com academy, NinjaTrader Q-levels lesson): indicator v6.1; you send a machine ID (enabled within 24 h) and enter an API key; levels arrive by API "as soon as calculated", in the video "every 60 minutes"; manual mode exists; history up to 30 days with NT playback; futures supported (demo ES; NQ via a QQQ-to-NQ ratio conversion); "intraday levels are not yet available natively for futures, so they are converted from SPX or QQQ" (their wording) -> their futures intraday set is construction B.
- Price (menthorq.com/pricing, read 2026-11-13): Premium $59 first month then $129/month; Pro $174.50 first month then $349/month. The page does not say which tier includes "Gamma Levels on Futures" or the NinjaTrader integration; ask support before any purchase. Not bought.
- Adequacy: (a) refresh ~hourly = fine for OI-based levels (section 4); (b) levels are an NT8 chart indicator fed by their API: D7 (a strategy) would need the values as data, not drawn objects - unknown whether the indicator exposes plots/series to a strategy; the API itself (JSON) is not documented publicly, so a Python sidecar reading it is unconfirmed; (c) 30-day history only: we cannot backtest their exact levels beyond a month (our own A/B reproduce the idea with 25 months); (d) B-like intraday set + A-vs-B disagreement of 300-700 pts on walls means their levels are not our levels - a test on their feed would have to be forward only. Verdict: adequate as a live feed ONLY IF a level beats the null in the exact engine on A or B (none yet), and only for hourly-OI-type uses; do not buy now. Our own native build (CME options statistics + 1-min option bars, ~$55 for 6 months, ~$0 incremental live via the CME feed we already have) replaces it at no subscription cost for the same hourly levels.
