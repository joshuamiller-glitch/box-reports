## The defect (ZL-3), verified
`d7lib._compose_d7` injects an exit (TH-L2 loss cut, take line) only if `kx > o[:,10]` (the second the resting 30% add fills). When the exit comes BEFORE the add fills, the exit was dropped: the trade ran on to its original outcome and the add could still fill and hit the target. FIX: the exit cancels the add (70% leg only): net = F x A (A recovered from the stored net: net + (1-F) x side x (fill px - entry px)), the exit delta applies to the 70% leg, add index -1. Rows with the exit AFTER the fill are unchanged. Independent verification: with the fix switched on, rows where an injected exit precedes the add fill: **846 library rows (145 OTE-62 B73 rows + 701 generic 70/30-split rows)**. By exit type: TH-L2 loss cut only (profit side empty) 125 rows (120 B73 + 5 generic); the remaining 721 rows are TAKE-LINE exits (price runs to the line before the dip-3 add fills, then the old code dropped the take). The 145 B73 rows match ZL-3's count. Example (loss-cut-only run, library row 2986, ST short NY-PM): exit second 25067829 precedes the add fill at 25068668; old net 54.8 pts-lots (full position incl. the add reaching target), fixed 41.8 (= 0.7 x 59.76, the 70% leg), then the cut delta applies to 0.7 lots. ZL-3's row 13940 is in a different index space (not a d-row of this table); the same defect class is reproduced on 125 loss-cut rows. Places checked where a resting add fill index can follow an injected exit: TH-L2 loss cut (fixed), take lines (fixed, same hook), U7 blackout (trigger reads the applied exit second; inert), locks (receive the final exit second o[:,3], unchanged), PE 45-s delayed entry (`kx > o[:,1]` uses the delayed entry: ok), WT wait rows (no add: ok). The re-target (B8) and S5 `rt` hooks write their own rows and are unaffected.

## Live question for the user (flag only)
Does LIVE D7 cancel the resting 30% limit (the dip-3 add or the OTE-62 B73 add) when a TH-L2 loss cut or a profit take line closes the 70% position before the add has filled? The library logic (d7lib) let the trade run on and the add fill after the cut time; if live D7 leaves the 30% limit working after the 70% has been cut or taken, the live book can open a new position after the exit (a loss-making orphan). The live code is the user's; only flagging.

## BASIS CAVEAT (BASE-4, added after the fill-basis finding; see DS3_TAKE_FILL_ARTEFACT_V13Y.md)
The take / tighten deltas of this page are measured against the MEASURED baseline (pts_lib - fill_cost_pts) while the engine baseline is basis N (target exits carry no limit-fill cost). A take on a trade that would have exited at the target is therefore credited fill_cost_pts (mean 3.39 pts per lot) that the N baseline never paid; placebo exits carry the same credit, so the placebo RANKS are internally consistent, but the MEAN and the drawdown cut of the take lines are overstated relative to a pure N-basis comparison. With nfix=True (N-basis consistent delta) the gated lines and the plain take LOSE the benefit: lock none 1-s, gated exact F9 cut +39% -> -32%, d mean -9.0k -> -21.7k/wk; plain 0.70 all F9 +57% -> +2%, d mean +7.1k -> -9.0k; L6M +57% -> +2%. Which baseline is right depends on whether live target limit orders suffer the measured 3.4-pt fill shortfall (basis M: then taking at 70% saves it and the first numbers hold) or fill at the touch (basis N). THIS IS A QUESTION FOR THE USER/LEAD before any take-line is called a finding.
