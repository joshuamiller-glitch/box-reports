# DS7_PROFIT_LINES_SPEC - exact semantics of the live profit lines, from DS7.cs v2.0 (539,225 bytes, /mnt/l2/l2vast/_ds7v20/DS7.cs = v1.9c logic + 3 Shadow switches) and THP_POLICY_D7_v2_9.txt (W-LB2, 2026-11-16 ~18:30Z; line numbers are DS7.cs v2.0)
**HEADLINE FINDING (code bug, confirmed by reading, consistent with the 11-15 log): the three book-reading profit lines with persist >= 2 can NEVER fire. ManagePolicyState L1790 `if (unreal >= 0) { b.StPersist.Clear(); ManageProfitState(...); return; }` clears the persist dictionary on EVERY closed second of a winning trade BEFORE ManageProfitState increments it (L1936: `cnt = ok ? cnt + 1 : 0; b.StPersist[r] = cnt`), and loss and profit rules share the one dictionary (L301). So cnt is at most 1 when `cnt < r.Persist` is tested: K7 `persist=10`, U7 `persist=5`, M7 `persist=2` are inert; only `persist=1` state lines fire (P7 lock 14.5 / 34.8, U7 lock 0, H7 lock 45 - the U7 and H7 locks did fire in the 11-15 log at 18:36:49). This is independent of the book fault (13-fold duplication, fixed in v1.9c) and still present in v2.0.** One-line fix (L1790): replace `b.StPersist.Clear();` by `foreach (var kk in b.StPersist.Keys.Where(k => !k.Profit).ToList()) b.StPersist.Remove(kk);` (clears only loss counters at a winning second, keeps profit counters; the profit counters are then reset by `cnt = ok ? cnt+1 : 0` itself, and by the loss path at L1793 when a blind book clears everything). A second effect to know: ManageProfitState returns at L1903 `if (!depthLive || stMedLevel <= 0) return;` without touching the counters, so a blind second neither counts nor resets a profit counter.
## 1. Where each line runs (evaluation cadence)
- A policy line with `win=`, `persist=`, `armlots=`, `engine=state` or `wall_ticks=` is a STATE line (parser L2825-2840 sets ThRule.StateEngine; ThRule fields L2792-2793). All others are ordinary per-print lines.
- **State lines**: StateTick (L1722) closes each exchange second and calls ManagePolicyState (L1778) for every book in a trade (one evaluation per book per closed second; catch-up seconds share one mid). ManagePolicyState computes unreal on the MID (L1785); winners (`unreal >= 0`, L1790) go to ManageProfitState (L1897); the give-back switch GbCheck (v2.0, Shadow) runs just before (L1789). ManageProfitState: updates the favourable mid extreme StFavExt/StFavSec (ties count, L1902); returns if the book is blind (L1903); computes tgtDist, stopDist, session; runs NkdTake first (L1908); then each profit state rule in file order (L1909-1948).
- **Per-print lines** (no win/persist/wall_ticks/armlots; takes at 0.95-0.9875, `lock` with persist=1 is a STATE line because it has persist=): ManagePolicy (L2972), called on chart-instrument prints, evaluated at most once per ThEvalFrequencySecs = 1 s (L2975-2976), on the LAST PRINT price (not the mid); `if (r.StateEngine) continue` skips state lines (L2982); the FIRST matching rule acts and `break`s (L3016). They do not need the book.
## 2. Feature definitions used by the three book-reading lines
| item | definition | lines |
|---|---|---|
| **pct** (profit) | unreal / tgtDist; unreal = mid (state) or last print (per-print) minus EntryPx in the trade's direction; tgtDist = |TargetPx - EntryPx| if a target order exists, else TradeTgtPts, else StopPts x TargetR (L1906; Feature L2880). TargetPx is re-based from the average fill after a split add; bracket lines set the target (`bracket K7 * target=59`, P7 58, M7 59.5 via ApplyPolicyBracket L2925). K7 pct 0.3 = +17.7 pts, 0.95 = +56.05; U7 pct 0.4 of 60 = +24; M7 0.3 of 59.5 = +17.85. | all |
| **delta_mult** (L1927) | `-Side x Delta60Window(now, win) / stMedLevel`. Delta60Window (L1588) = sum of deltaSamples.P over the last `win` seconds of WALL clock (now = Globals.Now at the evaluation, samples older than now-win dropped); a sample is created per chart-instrument print (L4060): sign +1 if price >= lastAsk, -1 if price <= lastBid, none if between; P = sign x volume (volume 1 if 0). Positive = aggressor selling into a long (against). stMedLevel = EWMA 0.001/s of the top-5 bid+ask mean level size (L1742). win from the line (`win=10` K7, `win=15` U7); default ThL2PulledSecs = 5 if win absent. Since v1.9c ticks are used once (TickSeriesFilter); before, every print was booked 13 times. | K7 5x, U7 20x |
| **tot_rel** (L2896 Feature) | `curDepthRel` if DepthLive else NaN. curDepthRel (L1687-1700 L2ThSnapshot, one snapshot per print) = (sum of bid-array sizes within 7.5 ticks of the bid touch + the same on the ask array) / depthBase[slot]; slot = ET half-hour 0..47; depthBase EWMA of curDepthTot8 per slot, alpha 0.02 for the slot's first 300 snapshots then 0.002; NaN until ThL2WarmupSnapshots (300, L542) snapshots in the slot. Uses the 20-slot arrays (NT8 delivers ~13 levels per side). | M7 2x |
| **wall_ticks=8** | only used by `wall_ahead_mult` (StateWallAhead L1891: largest single array level within wall_ticks of the mid on the AHEAD side / MedLevel); M7's line has NO wall condition, so wall_ticks=8 only marks the line as a state line (L2835) and is otherwise inert. | M7 |
| **win=** | feature window in seconds for pulled_mult / pulled_against_mult / delta_mult / sweep_against (state lines). `win=0` or absent = ThL2PulledSecs (5). M7 `tot_rel` ignores it. | K7 10, U7 15 |
| **persist=n** | number of CONSECUTIVE closed seconds the whole condition (all ANDed conds) must hold (L1936-1938); counter in b.StPersist[rule]; reset to 0 on a false second; **in v2.0 also zeroed every winning second at L1790 (bug above)**. The rule then fires ONCE per trade (b.StFired.Add, L1938; never re-evaluated). | K7 10, U7 5, M7 2 |
| **armlots** | loss lines only (arm = |pct| x stopDist x sqrt(lots/4) [v2] or sqrt(4/lots) [v1], clipped 15..50; L1816, L1847). Profit lines ignore it. | - |
## 3. Actions (set once at the fire second; ManageProfitState L1941-1948, StateExecute L1952)
- **lock X** (K7 `lock 0`; P7 `lock 14.5/34.8`; U7 `lock 0`; H7 `lock 45`): level = EntryPx + Side x X (L1941), RoundTick; PolicyTrailPx = level only if better than the current one (only ever tightens); in Live the exit is a MARKET exit ("PolicyTrail") on the first print touching the level (L3019-3024 in ManagePolicy, evaluated on every print while PolicyTrailPx > 0). No order is placed at the level. Shadow mode only prints "would set protective level".
- **step X** (M7 `step 10`): stepPts = X (10 if 0); favPts = (StFavExt - EntryPx) x Side at the fire second; k = floor(favPts / stepPts) - 1; k < 0 -> nothing set (and the rule is already consumed, StFired); level = EntryPx + Side x k x stepPts. **Set once; NOT ratcheted afterwards** (only `tighten` ratchets). At pct >= 0.3 (fav >= 17.85) k = 0 for fav in [10,20), so the first level is breakeven.
- **tighten X** (U7 `tighten 30`): level = favourable mid extreme -/+ X at the fire second; StTrailRule latched; then every closed second the level ratchets with StFavExt (L1950); exit on touch as above.
- **take** (state take lines and per-print take lines): market exit "PolicyTake" (state: decided at the close of the second, sent on the next print via StateExecute; per-print: RequestBookExit immediately); RequestBookExit cancels own stop/target first and sends the market exit (EXIT TIMEOUT 3000 ms in v1.9b+).
- ThPolicyValid gates everything (valid=2026-11-22 for v2.9; label day = ET + 6 h).

**What this means for JL2 as a base for live profit behaviour:** JL2 contains NONE of the profit policy lines (takes at 0.95-0.9875, the locks, NKD). Live fires the per-print takes on every winner that stalls near target (they only need prints), and the persist=1 locks/NKD take when the book is readable (since v1.9c about 99 %). The persist>=2 lines (K7/U7/M7) should be modelled as inert until L1790 is patched. Engine-side take/lock replay inputs: pct from the last print vs the bracket target distance, secs_ext from the favourable extreme time (per print), exit market at the next print.

## 6. W-EV confirmation (a1878b57f61f46389, 2026-11-16, ref RB_LAYER_SWITCHES.md "NOT in JL2")
JL2 has none of the profit policy lines: no per-print takes at 0.95 / 0.975 / 0.983 / 0.9875, no P7 / U7 / H7 locks, no NKD take, no K7 / U7 / M7 persist>=2 profit lines. Correction to the wording above: JL2's profit side is the native bracket (60-pt stop / 60-pt target, O7 40/90) plus sim.check_book_lock (engine default: give-back lock at 2R open profit keeping 50 %, and a week floor of 12R), a book-level rule not known to exist in live DS7 (switchable: ev_layers lock_off); other engine defaults touching profit: OTE-62 hold (ote_ahead) and the stack cut (both switchable). Loss-side lines JL2 does model: state cuts per book (K7 45/10x/w2/p3, P7 F3 ctx cells fresh 45/5x/w5/p10 and rechase 30/10x/w5/p2, M7 30/10/2/2, U7 30/60/15/5, A7 30/60/15/3, H7 15/30/10/2, O7 25/20/10/10), K7 flat -45, DAY-DONE C22; the engine state cut is driven by the engine book, not the live book, so it is not live-equivalent (the live book was ~79 % blind before v1.9c).
