# DYNEXIT_SPEC - what a winning dynamic exit would need coded in NT8 (W-DYNH, 2026-11-27, first version 03:25Z)
Research only. Nothing here is live and nothing is a result: no exit is called a winner yet (the walk-forward is on DYNEXIT_WF.md). Labels: SPEC = read from code (data/live_code/DS7.cs, the only D7/D8 live file on the box; there is NO D8Asia.cs in the repo, so every statement about D8Asia.cs below is a READING about what the D8 file would inherit if it is derived from DS7), READING = my interpretation, not verified in a running NT8.

## 1. What the live code can do today (SPEC, DS7.cs)
- Fixed per-book bracket: StopPts and TargetR (stop and target orders placed with the entry, ChangeOrder to move them). Per-session bracket CSV (ApplySessionBracket: "stop/target" per session slot, line ~2682) overrides the book's stop/target for the trade.
- Per-ENTRY bracket from the policy file (ApplyPolicyBracket, ~2125-2150): a rule may set the stop as k x ATR ("2.5atr", ATR14 RMA of 1-minute bars, atrNow) or points, the target as R x stop ("2r"), points, or a structure target ("or" = opening range, "pd" = prior-day level, StructureTarget), a time exit in minutes (PolicyTimeExitMin), conditioned on the book, the day regime / session and entry features (EntryFeature >= / <= x). So X1 (ATR-scaled), X2/X3 (partly: only "or" and "pd" levels), time stop are ALREADY expressible without new C#: they need policy-file lines only.
- Two-leg bracket (TwoLeg, Target2Order, DynTargetPx2, BeAfterLeg1): TP1 for part of the lots, TP2 for the rest, stop to entry after TP1. So X5 staged with ONE partial and breakeven exists; multi-level (3 legs) does not.
- Policy rules in trade (TH policy file, ~1320-1335 and 2200-2230): take / cut (market exit) and "tighten X" = protective trail X points behind the favourable extreme (profit) or beyond the adverse extreme (loss), exit at market on touch (PolicyTrailPx); lock (stop to entry + x). Features: pct, mins, secs_ext, dd, recov, vel30, eff120, delta60, imb5/imb10, wall_tgt / wall_stop. So a FIXED-distance trail and the lock exist; a chandelier (k x ATR) trail, swing trail, line trail (EMA/Supertrend), brick exit do not (READING: the nearest is "tighten X" with X a constant).
- Level 2: OnMarketDepth keeps the top 10 levels per side (Rithmic). wall_tgt / wall_stop = resting size AT the target / stop price, 0 when the price is outside the visible book. READING: with a 30-120 point bracket the target and stop are almost always outside the 10 visible levels (on the engine's mbp-10 the 10 levels span a median 2.25 points, p10-p90 2.25-2.5), so wall_tgt / wall_stop are zero for these books, and a LIVE X8 (cluster 30-120 pts away) cannot be seen from NT8 L2 at all. Only a data feed with the full book (MBO) can supply it.
- Data series: 1-minute, 5-minute and the books' own bars (AddDataSeries minute / second); no level files are read except the policy / bracket / state files (File.ReadAllLines of policy files). UW files: not read by DS7 (READING: the UW range forecast would need a daily file written by the box, read like the policy file).

## 3. Interaction with Trade Health (SPEC from the sets, READING from the code)
- The live Trade Health of a book is the policy / TH rules keyed to the book's tag (ec_hooks: scratch / flat / nft; ev_profit: takes and locks as a share of the TARGET). With a new exit the target changes, so a 'take at 0.95 of target' or 'lock at 0.8 of target' is re-defined by the new target (READING: for a recipe with no fixed target there is no target to take a share of, so those rules go inert in the engine and would need re-defining in D8). Exact pairs (exit alone N vs exit + live TH M) are the way the fight is measured; they are on DYNEXIT_WF.md section EXACT.

## 4. Order of coding if a family wins (READING)
1) per-entry brackets (X1 / X3 / X9 / time) through the existing policy-bracket file (no new C# for ATR-type; level distances written by the box); 2) chandelier / swing trail (X4) as one new policy action; 3) second staged leg; 4) SAR and flow only if a family shows real forward value after the random-entry null; 5) X8 only if the MBO cluster map shows value in the quick screen (data supply is the blocker).
