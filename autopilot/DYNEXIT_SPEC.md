## What a coded exit would have to specify (SPEC)
1. Forecast features, all causal at the signal bar close: ATR14 of the book's own bars (ctx.atr); trailing mean of the last 20 completed sessions' high-low range of the same session code (r20); HAR forecast of the session range = exp(OLS of log R_s on log R_(s-1), log mean R(s-1..s-5), log mean R(s-1..s-22)), fitted on the same session code on sessions before the current one, refit every 10 sessions, first forecast after 80 sessions (before that the book's own bracket applies); range so far = running session high-low at the signal bar; share of session time left = 1 - (t - session first bar) / median session length of that code.
2. Stop/target rules per recipe exactly as the names in DYNEXIT_WF.md (menu below). Distances are clipped [2.5, 150] pts (stop) and [2.5, 300] (target); the kernel skips a stop under 2 pts; a rule with no data on an entry falls back to the book's own bracket for that entry (READING: so the trade count is not changed by missing features); R:R filter and 'room < 4 pts' skip the trade (no blocking).
3. Level rules (X9): target = nearest level ahead at least 4 pts away (T1) or the second distinct level 2+ pts beyond (T2); stop = nearest level behind at least 3 pts away plus buffer 1 tick-equivalents (1 pt for 'S4', 0.25 pt 'S1', 2 pts 'S8'), never wider than the book's own stop; confluence = levels that have a level of another type within 5 pts; 'any' = union of all types except round numbers. No level -> the book's own value for that side.
4. Pick rule (the existing exit rule, unchanged): eligible = L6M > 0, L3M > 0, >= 20 trades in L6M, no prior calendar year more than 30% worse than the L6M weekly rate; best = lowest ulcer (RMS drawdown of the weekly curve since week 0), then highest L6M; no eligible recipe = keep the book's own bracket. Re-pick every 13 / 4 / 2 weeks using only weeks before the date.
5. For the live system: a re-pick every 2-13 weeks means the config of every book changes by file, not by code: the DS7 would need a 'bracket <book> <session> stop=<expr> target=<expr>' grammar with expressions in {pts, k*ATR14, k*R20, k*HAR, level:<type>:<n>:<buffer>} and a per-session range-forecast feed (HAR needs the session ranges of the last 22 sessions per code: available live). The THP grammar extension in DS3_REBUILD_S3_ENV already asks for stop=/target=/timestop=/halfoff=; the expression forms above would be additions.
