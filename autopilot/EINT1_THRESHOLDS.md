* UNIVERSE: every standalone library base-bracket trade of the book (`dipentry/trades_arm.parquet`, the THP trade index, via `out/missed/eint1/feat_trades.parquet`), NOT only trades a lock engine took, NOT signals a book's own logic suppressed. * Features included (40): every ABR signal-strength feature (sig_slope, sig_kelt1/3, sig_hma_sp, hma_slope, sig_st1/st5/st10 age and dist, sig_pb30_atr, pb_speed, sig_lastbar_rng_atr, atr_ratio, atr_pts, bar_vol_rel, body_abs/signed, z_vwap_eth/rth, sd_pd_hi/lo_atr, sd_pdrth_hi/lo_atr, sd_sess_hi/lo_atr) and every HTF feature (htf_tr20/50, htf_pd_pos, htf_d_open_atr, htf_wk_open_atr, htf_vwap_atr, htf_on_range_atr, htf_on_pos, htf_fh_atr, htf_gap_eth/rth, htf_pd_range_atr, htf_on_ratio). Not included: confluence counts (cf_/n_same, integer counts, not tercile features).
* Use: a rule "feature < q33" / ">= q67" as in `eint1_policy_candidate.txt` (strict `<` for the bottom bucket, `>=` for the top). Values are the 20260206 cut, i.e. they lie inside the windows on which the four rules were selected (EINT1_FEATURE_SPEC.md section 10).

## 1. Monthly refresh script
`l2vast/ds3/code/eint1spec/refresh_thresholds.py`
```
python3 -I refresh_thresholds.py --window-end YYYYMMDD [--table PATH] [--out PATH]
python3 -I refresh_thresholds.py --window-end 20260206 --check autopilot/eint1_thresholds_frozen.csv
```
* Rule: the exact trailing-12-month rule above; `--window-end` = the last label day of the month being published (the window never includes anything later: the table is cut to label_day <= window_end first).
* Table path: `--table` (default `out/missed/eint1/feat_trades.parquet`, capped 20260206). It must have the same schema (columns book, label_day, and the 40 features). **The default table ends at 20260206, so a monthly refresh needs a feature table rebuilt on the extended library**: the weekly library-extension job (RUNBOOK_WEEKLY_EXTENSION.md, which extends trades/bars/L2 each Saturday) must be followed by an `ei_feat.py` run on the extended trades_arm (its CUT is currently hard-coded 20260206, so the job/user must edit it and the `ei_policy.py` / `ei_nightly_refit.py` guards, which require `EINT1_LIVE=1` beyond the cap). Neither runs automatically today; the refresh needs that weekly job (or the user) to supply the table, then one command writes `eint1_thresholds_frozen_<window_end>.csv` (never overwrites; refuses if the file exists).
* Cap guard: `--window-end` > 20260206 exits with REFUSED unless `EINT1_LIVE=1`. Research agents (this one included) did not run it past 20260206 and opened no post-cap file.
* Self-check: re-running with `--window-end 20260206 --check eint1_thresholds_frozen.csv` regenerates the whole file (tie-out and comment lines are deterministic: no timestamps) and compares bytes: **BIT-FOR-BIT IDENTICAL** (run twice, before and after a tidy-up edit). Also run the tie-out line of any new file: the four shipped numbers are only expected on the 20260206 file; for later months the line is informational.
* Monthly drift report to read on each refresh: compare the new q33/q67 to the prior month for the rule features (HM sig_slope, KB/PE/HM sig_st1_dist_atr).

The study's rule is `ei_cat.py:crank`: rank = (#earlier same-book values strictly smaller)/n_earlier, min 100 non-NaN prior values, history inserted after ranking, pooled over sides and sessions; B3 = rank < 1/3, T3 = rank >= 2/3.

|---|---|---|---|---|
| 1 | Universe | every library base-bracket trade of the book (47,131 across 11 books; HM 4,156, KB 5,500, PE 5,361), including trades the lock engine would skip and those with no live fill | the signals the chart itself computes for the book on the live data (as recorded in the chart history); excludes anything the chart's strategy logic suppresses before the signal, and signals in the no-entry windows (18:00-18:04 label minutes; 15:00-16:54 ET per the live windows map) if the chart does not compute them | different population: the live distribution is conditional on the live gating. ## 3. How far the bucket moves with a short warm-up (capped data, `code/eint1spec/sim_option4_vs_study.py`, `out/eint1spec/option4_vs_study_sim.csv`)
Setup: eval signals = label days 20250207..20260206 (the last 12 months; HM 1,829, KB 2,558, PE 2,510 signals), standalone-book trades pooled over sides and sessions. "Chart history of h months" = the book's earlier signals whose label_day lies within h calendar months before the decision signal (all signals, taken or not), rank = strictly-smaller share, min 100. Frozen vs study with no warm-up question (full-history S as reference): F differs from S on HM slope 4.3% (action 2.2%), KB 0.35% (0.16%), PE 1.0%, HM dist 1.5% (0.16%); M differs from S on 1.4 / 1.3 / 1.1 / 2.1%. HM sig_slope is the unstable one: its distribution drifted so that the full-history cut and the trailing-12-month cut disagree on 4.3% of the last year's signals.

Reading: even a 3-month warm-up changes the bucket for 2-5% of signals (rule action 1-3%), 6 months 1.3-4%, 12 months 0.4-2.8%; the action changes are a small share of trades, so the signed P&L effect is small relative to noise. P&L consequence (standalone trades, raw multipliers, per-trade sd about 57 pts): the sum over the action-changed signals of (multiplier difference x pts) for warm 3 / 6 / 12 m vs S is HM slope -936 / -724 / -550 pts (61 / 40 / 14 changed signals; the rule's own gain in this window is +1,301 pts, so a 3-month warm-up gives back most of an in-sample, selected gain, but 1 SE of such a sum is about 57 x sqrt(n) = 445 / 360 / 213 pts, so it is about 2 SE and not distinguishable from selection noise); KB +323 / +178 / +101 pts (33 / 22 / 16 signals, SE 330 / 270 / 230); PE +2 / -112 / -86 pts; HM dist shadow +173 / +278 / +88 pts. The sign pattern is mostly that the study's tercile cut is the better-fitted one on the selected window (the rules were selected on this window); treat the P&L figures as upper-bounded noise, not an estimate. USD columns in the CSV are at the standalone library lots (HM 10, KB 5.2, PE 5.6 lots x $20/pt), unmatched, not the lock engine.

Caveats: signals in the chart's history are assumed to equal the library trades (row 1 of section 2 is not simulated); the 3-month history is "the previous 3 months from each decision date" (a chart that started on a fixed date has a growing history, which converges toward the 12-month column); no per-session or per-side ranks; no overlap/lock effects.

## 4. Comparison plan for next week (option 4 vs frozen thresholds, live)
Frozen mode loads `eint1_thresholds_frozen.csv` (the latest published window_end <= the decision date; refresh monthly with section 1) and buckets the same feature values as the live expanding rank.

**Per-signal log fields D7 must write (one row per signal of each EINT1-ruled book, whether or not the rule skips it, whether or not it trades):**
1. `ts_signal` (entry second UTC), `label_day`, `book`/`tag`, `side`, `session`, `signal_id` (stable key for joining to the fill log);
2. `feature` and `feature_value` (the exact value, full precision, per rule feature: sig_slope, sig_st1_dist_atr; plus sig_st1_age, hma_slope, pb_speed if ported), `feature_nan` (0/1);
3. expanding mode: `exp_n_prior` (history count used), `exp_rank` (strictly-smaller share, NaN if n_prior < 100), `exp_bucket` (B/M/T/U for unranked), `exp_action` (multiplier the rule would apply), `in_history` (1 if this signal was inserted into the history after ranking; must be 1 for every signal, taken or not);
4. frozen mode: `frz_window_end` (label of the file loaded), `frz_q33`, `frz_q67` (the values used), `frz_bucket` (B/M/T/U), `frz_action`;
5. `mode_live` (which mode actually sized the order: exp or frz), `mult_applied`, `taken` (1 traded / 0 skipped by the rule / 0 skipped by lock or window or other, with `skip_reason`), `lots`, and the fill/exit reference (order id) so P&L joins from the strategy trade log; for skipped signals the shadow outcome comes from the engine replay (`ap_live_vs_engine.py` style) of the same signal.

**Statistics to read:**
* Bucket disagreement rate = share of ranked signals with `exp_bucket != frz_bucket` (and the rule-action disagreement rate = `exp_action != frz_action`), per book, per week, with the 3-way contingency table. Expected from section 3: about 1-5% (action 0.5-3.4%) at a 3-6 month history, below 2% at 12 months, HM sig_slope the largest. A rate well above that signals a universe/gating difference (section 2 row 1) or a feature bar-source difference, not a threshold effect.
* P&L consequence = sum over the disagreement signals of (`exp_action` - `frz_action`) x signal pts (engine replay for skipped signals), in pts and in dollars at live lots, with its standard error (sd of pts about 57 per standalone trade x sqrt(count)); compare to zero. With about 0.3-1.2 action-changed signals per week per book (14-61 per year in section 3) the first weeks cannot discriminate (the weekly SE exceeds any plausible effect); read the cumulative number only after about 26 weeks and report the disagreement rate in the meantime.
* Also read: the weekly shift of `frz_q33/q67` vs the realized exp rank cut (the live expanding cut in feature units: the 1/3 and 2/3 empirical quantiles of the chart history), and the count of unranked signals per book.
