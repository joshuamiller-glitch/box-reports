# ENGINE_V3_DEF AMENDMENT 2 (BASE-4, dated by log/mtime: see DECISIONS.md line for its sha), before further V3 runs. Rulings of the lead on CHAR-C QA_ENGINE_V3.md.
1. Gate definitions: GATE0_SPEC.md (S4a; sha in DECISIONS.md) GOVERNS. G3 = cut pairs / (live cuts + engine cuts - cut pairs), a cut pair = matched pair, both cuts, exit seconds within 10 s; G1 matched/union via the compare tool; G2 net gap; G4 cut dollars over ALL cut trades. Exit-type agreement and maxDD gap are informational. The official scorer is code/gate0/gate0_check.py; BASE-4's gate0.py (own matching; G3 'recall') is a quick-look tool only and is superseded for every number that is reported. The iteration log is autopilot/GATE0_ITERATIONS.md.
2. Header times in ENGINE_V3_DEF.md (19:45Z) and Amendment 1 (20:00Z) were written by estimate and are WRONG; the log lines in DECISIONS.md carry the real times (date -u at logging) and the file mtimes are the truth; those two files are not edited (their sha256 are logged).
3. Trigger rows: fabricated trigger rows (upnl/p5/median set so that the engine fires) are NOT accepted beyond a Gate 0 calibration preview. The harness engine_v3_run.py (second version, sha256 logged) takes the REAL feature rows of ZL-2's series: the stored K rows of the covered trades are replaced by the real row at the real decision second (all feature columns unchanged); only the exit attributes ts (= fill second = decision + latency) and cut (price of the fill second - c - base) are set; it prints the number of fabricated feature values (target 0), the number of real trigger rows and the number of engine cut exits, and 'engine cuts == real trigger rows' (with the reasons for any difference: trigger after the trade's exit, trigger before entry, loss-line gate, lock exit first). The week-preview series built by BASE-4 (mk_k1s_week.py) carries only upnl, p5, med from ZL-2's dense.npz and DEFAULTED other columns (ne5/ne10/ne30 = 1, rest 0): every iteration run on it is labelled PRE-PROOF-PREVIEW-FABRICATED-COLUMNS and is never a Gate 0 pass; the Gate 0 iterations use ZL-2's real series (all columns). A pass that needs a fabricated row is labelled PASS-WITH-FABRICATED-ROWS and A-F do not start on it.
4. Freeze point (named at freeze time, list and its sha256 in DECISIONS.md): ENGINE_V3_DEF.md + Amendments 1..n, the engine harness file(s) engine_v3_run.py, TH_RULE_V3.md + its addendum (selected N), FILL_MODEL_V3.md and fillsim.py, the v3 tree manifest, GATE0_SPEC.md + gate0_check.py.
