## 1. Partition and ownership
FD-LIQ owns candidates whose instrument is NQ, ES or RTY (and the ES+YM, ES+RTY, RTY+YM relative-value pairs: one leg has MBP-10) -> FULL stack (state cut TH-L2-S scored per book as for NQ, book-derived zones, L2 gate, all price layers). FD-NOL2 owns everything else (YM GC CL ZN ZB 6E 6J MBT NKD BTC, the 6E+6J pair, DAILY books on those) -> "NO-L2 STACK" (ER sizer, price-path TH both sides, structural zones, locks, cooldowns, stack rules, near-target take). `F.owner(instrument)` returns 'LIQ' / 'NOL2'. Candidates not exported as trade lists but defined on disk are in candidates.parquet with `trades_file` empty (rebuild queue, section 8).

## 2. Files (all under /mnt/l2/l2vast/_th_fd/)
- `candidates.parquet` (+ autopilot/FD_INVENTORY.md): one row per candidate (id, instrument, owner, session, family, src_dir/src_file, source_cell, status in its source page, what killed it, naked mean/maxDD per window, trade-list path, definition path). Phase-1 rows (6,734 exported trade lists) are in `candidates_phase1.parquet` (the machine-made columns); the status columns are merged in by FD-CORE (phase 2) - do not write these files.
- `trades/<id>.parquet`: the NAKED trade list in the common schema (section 3). One file per candidate id. Never overwritten after the first publish except by FD-CORE (a `trades/_manifest.json` records the build sha).
- `trades_dressed/<id>@<dressKey>.parquet`: DRESSED lists written by the owners (same schema + the dress columns of section 4).
- `ledger_<owner>.parquet` (owner = FD-LIQ / FD-NOL2 / FD-CORE): rows from `F.score_row` (section 6); merged by `F.merge_ledgers()` and by the page generator code/th_fd/fd_page.py.
- `null/*.npz`: timing-placebo draws per (id, dress, seat); `F.family_p_fd()` builds the family max-stat null over them.
- `FD_NAKED_SEATS.parquet`: naked seat screen of all 6,734 lists (no exposure, no placebo) - the starting rank for dressing (rank on `seat_add_eq_cut_L6M` / `seat_weakest_inc_eqcut_L6M`, see section 7).

## 3. Id naming and the trade schema
id = `<INSTR>.<family>.<h8>` (INSTR with '+' written '-', e.g. YM.vwap_reject.1a2b3c4d, ES-YM.T2F_RVESYM.9f8e7d6c, NQ.LRS.5e4d3c2b); h8 = md5 of `<src_dir>/<src_file>` (stable). Dressed key: `<id>@<dressKey>`, dressKey = short text of your own (e.g. `er2_pp3_ibz1`), recorded in `layers` as JSON/text.
Columns of trades/<id>.parquet (sorted by entry_ts): `entry_ts, exit_ts` (epoch s, int64), `side` (+1/-1, int8), `ld` (label day of the EXIT, int32, 17:00 ET roll, Sat/Sun -> Monday = instr2_eval / SZ convention), `session` (asia london pre nyam nypm close; NQ-style ET definitions; 'daily' for DAILY books), `risk1` ($ risk of ONE lot at entry = stop distance x point value + costs; NaN for hold books without a stop), `pnl1` (net $ of ONE lot, fees and slippage as in the source screen - measured fills of the source, fees per outputs/FEES.md at the time; NOT re-fitted here), `lots_src` (lots of the source screen at R=$1,200/trade, informational), `frac` (1 = fractional-lot instrument BTC/MBT/NKD screens: lots scale linearly), `entry_px, exit_px, stop_px, tgt_px` (NaN when the source did not keep them), `rollx` (1 = alive across a contract roll with stitched prints -> weight 0, same meaning as sz_core ROLL-EXCL; 0 for all instr2 lists: they were run on back-adjusted continuous 1-min series (instr2_adj / series_*.npz), so no stitched-print artifact; the NQ replica books (exact engine) use Base.rollw), `roll_alive` (informational, 0 in phase 1).
Equal-$-risk lots: `F.lots_for(df, R, cap)` = clip(floor(R/risk1+.5), 1, cap) (rows with no stop keep lots_src); fractional rows = R/risk1. `cap` = participation cap (lots on) `F.LOT_CAP[instr]` (NQ ES RTY YM 10, GC CL 6, ZN ZB 20, 6E 6J 10, MBT 20, NKD 6, BTC 4; the live stack's largest single trade is 7 lots). P&L of a trade = pnl1 x lots. Daily series on the stack calendar (Z.DAYS = business days 2023-04-03..2026-11-05): `F.cand_daily(df, R, cap, scale=1.0, lots=None)` (booked on the exit label day; rows with rollx==1 weight 0; trades before 2023-04 or after 2026-11-05 drop out of the daily series but stay in the file).
Data ends: the 1-min bar books end 2026-10-16 (YM ZB 6E 6J NKD BTC MBT), NQ-family exports 2026-10-30; so the 11-02..05 live week is NOT in most lists (page says "n/a: list ends <date>", never a pass).

## 4. Dressed lists (what the layer scorers write)
Same schema, plus `m` (float lot multiplier, 0 = skip, ONE rounding after lots_for: max(1,floor(l*m+.5)); `F.lots_for` applies it automatically), `cut` (0/1 trade exited by the dress), and `pnl1` already re-computed for the dressed exit (cut / take / near-target / lock). `risk1` stays the naked entry risk (the dress does not change the 1R at entry). One row per kept trade; skipped trades stay with m=0 so counts reconcile with the naked list. The dress description (layer settings as D7 panel values / policy lines) goes in `layers`; `stack_label` = 'FULL STACK' (LIQ) or 'NO-L2 STACK' (NOL2); `l2` = 'yes' / 'no (depth not on box)'.
Dressing and seat testing both see only information known at the signal/entry second (causal; forward-only placebos).

## 5. Seat test (the stack's drawdown is the metric)
`F.stack()` -> S: S.D[book] = S1b-COMB daily $ per book at live lots (KB PE SM HM MV PB OD), S.stack = sum, ROLL-EXCL applied (33 trades), windows L1M..X' as of 2026-11-09 (sz_core.WIN), all-weeks maxDD / worst-20 / Ulcer, carry week dropped from MEANS only. `S.contrib[book]` = Calmar(stack) - Calmar(stack without the book) on L6M; **weakest = argmin = MV** (contribution -3.21 Calmar: the stack's L6M Calmar RISES by 3.2 when MV is removed; others: KB +1.47, PE +5.38, SM +3.73, HM +3.50, PB +0.47, OD +0.60). Live per-trade risk `S.R_book[b]` = $1,200 x the book's mean lots (KB 1,371, PE 5,349, SM 3,175, HM 2,084, MV 1,397, PB 1,200, OD 1,200).
`F.seat_test(df, seat=('add','weakest','corr'), R_add=1200, cap=None, with_exposure=True)` -> {seat: metrics}:
 - add: stack + candidate at risk R_add per trade (default = the $1,200 one-lot unit).
 - weakest: stack - MV + candidate at MV's per-trade risk.
 - corr: stack - the live book with the highest weekly correlation to the candidate (`S.most_correlated`) + candidate at that book's risk.
 Metrics per window (L1M L2M L3M L6M HOLD MID PRE X'): mean_w, dd_w, w20_w, ulc_w, calmar_w, cut_w (% maxDD cut vs the live stack), dmean_w; at EQUAL STACK MEAN (one global lot scale eq_f so the L6M mean equals the live stack's): eq_dd_w, eq_w20_w, eq_ulc_w, eq_cut_w; corr_w / corr_d (candidate vs stack weekly / daily) and corr_ok (both <= .30); exposure: maxlots_cand / maxlots_stack / maxlots_both and same_side_* (event sweep, max lots on at one time and same-side lots); cand_mean_L6M, cand_dd_L6M.
 **Replace seats are credited only for what the candidate adds beyond the DROP-ONLY row** (live book removed, nothing added; MV alone gives +14% L6M cut at equal mean, so every candidate would "replace MV and cut maxDD" for free): keys drop_cut_w, drop_eqcut_w, inc_cut_w, inc_eqcut_w (= candidate stack minus drop-only stack, in percentage points of the live maxDD).
 `F.clears(r)` = eq_cut_L6M > 0 and eq_cut_PRE > 0 (tolerant: one of them >= -3), applied to the seat row (replace seats: apply it to inc_eqcut_* by passing the row built from them - the page does this).
Placebo: `F.placebo_days(df, R, cap, remove=None, B=200)` = timing placebo (cheap, all candidates): the candidate's own trade P&Ls re-assigned to random label days (same count, own P&Ls so mean/vol preserved; forward-only, no outcome information), equal-mean cut draws on L6M / PRE / X'. Finalists additionally get the random-ENTRY placebo (same count, same session, re-simulated on 1-min bars with the instr2 simulator) - FD-CORE runs that, owners need not. Family null: `F.family_p_fd(seat)` (max-stat over every saved draw set, z-standardised, L6M and PRE; independent-cells => conservative). Walk-forward of the whole dress-and-pick procedure and held-out live weeks (frozen file 2026-11-02..05 only; 11-08 and later is not on the box) are run by the owners for their own joint stage and recorded in their ledger columns `wf_ok`, `live_total`, `live_note`.

## 6. Ledger row (one call)
`row = F.score_row(cid, df, instrument, session, stage, dress, layers, stack_label, l2, B=100, **extra)` -> dict with: owner id instrument session stage (naked | screen:<layer> | joint | dressed) dress layers stack_label l2 n_trades R cap; own_mean_/dd_/w20_/ulc_/nwk_<w> (the candidate alone at R=$1,200, instr2 carry convention: weeks 202629-39 / 202506-09 / 202321-41 dropped from means, all weeks in maxDD); seat_<add|weakest|corr>_<metric> (section 5); weakest_book; p_plc_<seat>_<L6M|PRE|X'>; clears_<seat>. Add your own columns freely (wf_ok, live_total, layer deltas, carrier layer, L2-price quote ...). Write with `F.write_ledger('FD-LIQ' or 'FD-NOL2', rows)` -> /mnt/l2/l2vast/_th_fd/ledger_<owner>.parquet (rows with the same (id, stage, dress) are replaced). For layer-screen rows use stage 'screen:er', 'screen:th', 'screen:zone', 'screen:cool', 'screen:profit', 'screen:lock'; joint rows 'joint'; the pick 'dressed'. The page ranks `dressed` rows, shows the naked row (stage 'naked') beside it, and lists the carrying layer from your `layers` / `carrier` fields.

## 7. Starting rank for dressing (use it; it is a screen, not a verdict)
FD-CORE publishes /mnt/l2/l2vast/_th_fd/FD_RANK.csv (per owner) from the naked seat screen: priority = candidates whose naked own L6M mean > 0 or whose naked add/replace seat already lowers L6M or PRE maxDD at equal mean, one best candidate per (instrument, session, family) first, then the rest; NOT a filter - a candidate that is negative naked can still be dressed (the directive's point), so work the list top-down but cover every (instrument x session x family) group at least once. FD-LIQ: the NQ/ES/RTY candidates; FD-NOL2: the rest. Expect many near-duplicate parameter variants (a family at 100+ parameter cells): dress the family's top-3 by naked HOLD/L6M mean and the family's median cell, not every variant.
