# FEE_AUDIT_INSTR2: per-contract fee and slippage audit of every T-INSTR-2 / T-FIND grid (S4b, 2026-11-06 02:22Z)
Code audit, prereg-free (lead order after the BTC / MBT fee omission). Method: for every grid the cost definition was read from the code that scores it, and one trade per representative pipeline was reproduced by hand from raw bars or frame prices (script l2vast/ds3/code/t2/fee_audit_repro.py). FEES.md (outputs/FEES.md) lists only ES 4.84 (NT-published), NQ 4.84 (PROXY ES), MES / MNQ / M2K / MYM 1.78, MCL 2.08 and the 6E addendum 5.30. Z2's instr2_sessions.json (the shared cost table) uses: ES, NQ, RTY, YM, GC, CL, ZN, ZB, 6J, BTC, NKD = **$4.84** (PROXY-STD, te2_lib standard; FEES.md has no entry for RTY, YM, GC, CL, ZN, ZB, 6J, BTC, NKD), 6E = **$5.30** (FEES.md addendum, weak exchange component), MBT = **$1.78** (PROXY-MICRO = FEES.md MES value; not CME-published here). Slippage ticks (proxy): market entry 1 tick, stop exit 2 ticks, market / time / flat exit 1 tick (BTC, MBT, NKD: 2 / 3 / 2 ticks = 10 / 15 / 10 points).
## Result in one paragraph
**One family of grids charged no fee: S4b's T-INSTR-2 stage-1 grids on BTC / MBT / NKD (t2_grid.py, the family null, the Keltner cluster follow-up).** Every other T-INSTR-2 / T-FIND pipeline charges the per-contract round-trip fee on every trade, in the stage-1 screen as well as in the final evaluator. Two smaller cost-model differences were also found (below): the library screen FM.sim_bars charges no ENTRY slippage (stage 2 does), and S4b's native ZN / ZB books omitted the half fee on target exits (fixed, no count changed). Re-running the three crypto grids and NKD with the fee: the persistent-cell clusters shrink, the best t falls, **no label moves up and the BTC / MBT WATCH is weaker**; no ES / RTY / YM / NQ / GC / CL / ZN / ZB / 6E / 6J / NKD-native label changes.

## Cost-model differences found (not omissions of the fee)
1. FM.sim_bars (ZL-1 library screen used for stage 1 by Z3 and S4a) charges NO entry slippage (entry at the bar open), only stop-exit slippage 2 ticks, market-exit slippage 1 tick, 0 on targets, and the full fee. The evaluator stage 2 charges entry + exit slippage + fee on every trade. Stage-1 screens are therefore about 1 tick (0.04-0.1 R on rates, more on CL / GC) kinder than stage 2; final labels come from stage 2, so no label depends on the stage-1 asymmetry, but any stage-1 'best-of' ranking is slightly optimistic.
2. The shared json rt_market_in_stop_out is charged on EVERY exit (target, time, stop) in all evaluator callers that pass it with stop_extra 0: this over-charges non-stop exits by 1 tick (conservative).
3. instr2_sessions.json rounds fee_pts to 6 decimals: for 6J (pv 12.5M, tick 5e-7) it shows fee_pts 0.0 and rt_market_in_market_out 1e-06 (true 1.39e-06, 28 percent low), while rt_market_in_stop_out 2e-06 (true 1.887e-06) includes the fee and is rounded up 6 percent: any 6J consumer using rt_market_in_market_out would be 28 percent light on cost; no 6J pipeline found uses that field (t2fx uses FEE/PV + 2 x TICK directly).
