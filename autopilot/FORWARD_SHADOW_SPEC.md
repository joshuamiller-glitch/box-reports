# FORWARD_SHADOW_SPEC - the forward shadow register for the Sunday brief's SHADOW rows (SH-1, 2026-10-31)

Spec + prototype only. No data after 2026-02-06 was read (UNTOUCHED sealed). Files: `autopilot/shadow_log_schema.csv` (the log, 95 fields), `l2vast/ds3/code/shadow/{shadow_score.py, make_synthetic_log.py, test_shadow_score.py}`. Start: the first signal after Sunday 2026-11-01 18:00 ET (scorer refuses real rows before 2026-11-01 23:00Z). Weekly line to MORNING.md every Monday in the HM forward-register slot (separate scorer; HM a30_w10 stays the sole HM primary and is not touched). Numbers below are research L6M values from the cited reports; every one is post-hoc/LEAD at best.

## 0. Common rules (apply to every rule)
* **Clock.** All state is a pure function of data stamped <= the signal second t0 (the second the book's signal fires, = when the live entry is submitted). Bars are CLOSED bars only (the last bar whose end <= t0; the bar containing t0 is never used). Exception: PE45 is evaluated at later 45-s bar closes by design (section 1).
* **Log every signal** of every book (K6 P6 U6 H6 live; S6 W6 and others as paper rows, `lots_stack` = live lots else research/2.35), including signals the live book does not take (`taken=0`, `blocked_by`). A missing state is logged blank with a reason, never as "no fire". Scorer reports the blank rate and excludes, never zero-fills.
* **Counterfactuals are computed offline from tape**, so the log holds the inputs (closes, bars, prices, lines), not outcomes. Live outcome (`live_pts_ppl`, net of fee/slippage, points per planned lot) is joined from the real fills after close.
* **Units** (reported for each rule): per planned lot (pts/signal, all in-scope signals in the denominator, week-clustered SE, MDE = 2.8 SE, equal-risk rescaling for sizers), per contract of final position, same-trade stack $/wk at the actual live lots (x $20/pt) and at research lots. The lock-engine re-entry effect (76% of the Asia-cut gain, and the governor reading planned- vs sized-lot R) is NOT in the weekly line; it is replayed offline from the full signal log by the stack2/sundaystack engine on request (that is where open question 3 gets answered).
* Readiness on Monday: **R2, R3, R5, R6, R7 need only existing D6 state or fills**. R1 needs a 45-s bar series, R4 a rolling 8-line file, R8 an ES feed bar, R9 a daily HTF FVG file; until D6 has them the fields stay blank and the scorer says NO_DATA.

## 2. The per-signal log (full list: `shadow_log_schema.csv`)
Four tables. **signals** (one row per signal, every book): `signal_id, ts_signal_ms, ts_eval_ms (<= t0+1 s), trade_date, book, session, side, signal_px, stop_d, tgt_d, lots_live, lots_research, lots_stack, taken, blocked_by, live_entry_mode, live_config_ver`, then per rule the state variables of section 1 (`er20_5m, er_bar_end_ts, er_closes, er_mult_kb, er_mult_oth, hyp_lots_er; zone_file_ver, zone_lines, zone_fire20; prev_book_*, second_fire30; es_*, nq_*, atr, eslead_lag_z, eslead_mult; hmfvg_*; pe45_event_ts, pe45_limit_px`) and the hypothetical action, plus the joined outcome (`live_close_ts, live_exit_type, live_pts_ppl`). **pe45_bars** (signal_id, seq, bar_end_ms, o h l c v). **stack_events** (R5 rows, with books_same / books_opp lists). **stops** (R7). Offline replay writes **cf_results** (rule, signal_id, cf_pnl_pl, cf_lots_pl, cf_status ok|nofill|missing_tape, replay_ver). Counterfactual outcomes of sizers and skips need no replay (linear in the logged multiplier / zero); R1 and R5 do.
Audit gate (printed on every weekly line): the scorer recomputes ER from `er_closes`, the zone flag from `zone_lines` and the PE45 event from `pe45_bars` and reports the mismatch rate vs D6's logged value; > 0.5% means the D6 implementation is wrong and the week's rule line is void.

## 3. Weekly metrics and the pre-registered decision rule
Weekly line per rule (MORNING.md, Mondays): n signals, fire rate and fires/wk, delta per planned lot (SE, one-sided p, week-block bootstrap 90% CI), per contract live -> rule, same-trade stack $/wk at live lots and research lots, kept vs skipped (n, mean pts/lot, $/wk) for skip rules, unscored count, audit rates, stop A/B line. Run: `python3 shadow_score.py --signals signals.csv --cf cf_results.csv --stops stops.csv --bars pe45_bars.csv`.

**Decision rule (fixed now; applied only to the numbers the scorer prints).** Primary metric = delta per planned lot (equal-risk for sizers) for R1-R4, R8, R9; same-trade stack $/wk at live lots for R5, R6. theta = 0.5 x the research L6M estimate (winner's-curse haircut). With the research MDE (2.8 SE at 27.2 weeks), the weeks W_on at which a true effect of theta reaches one-sided p < 0.05 is W_on = 37.5 x (MDE/est)^2.
* **SHADOW -> ON-eligible** (all of): weeks >= W_on; delta >= theta; one-sided week-clustered p < 0.05 after Holm over the rules eligible the same week; same-trade stack $/wk > 0 at live lots; fire rate within 0.5-2x of research; audit mismatch < 0.5%. ON itself is the user's decision (post-hoc rules never switch themselves on).
* **SHADOW -> OFF**: HARM at >= 13 weeks (delta < 0 with one-sided p(delta<=0) > 0.95); FUTILE at >= W_on/2 weeks (delta + 0.84 SE < theta). No other stopping; the weekly line is descriptive between checkpoints (no peeking decisions).
* Paper rule R8: no ON path; revisit only if its increment over the ER sizer is >= +0.34 per planned lot with p < 0.05 after 52 weeks.

Calendar timeouts are the user's call, not automatic.

## 4. Simultaneity (shadow rules must not alter live behaviour)
1. Read-only: the shadow path creates, modifies or cancels no order, and its multipliers and flags feed nothing into lots, stops, targets, day/week locks, governors or the ON-set lines. Hypothetical lots exist only as logged columns.
2. Isolation: shadow evaluation runs after the live decision (ts_eval >= live submit) or on a separate thread; exceptions are caught and fail-open; if shadow evaluation exceeds 50 ms at the 99th percentile it is disabled, not the live engine. Writes are append-only and buffered.
3. No lookahead and no live influence: state uses data stamped <= t0 and closed bars only; counterfactuals are computed after the fact from tape by a separate process; the live outcome is the real fill.
4. Each rule is scored marginally against the live book as it is; interactions (ES on top of ER, cut50 on top of zone skip) are offline replays, not separate live paths. A change to the ON set bumps `live_config_ver` and starts a new scoring segment (scorer warns on mixed versions).
5. The only live-behaviour change in the register is R7 (order type by date parity), run on its own: no other ON-set change in the same books during the test unless compared within the same set (FORWARD_STOP_AB.md).
6. Sealed data: prototypes were tested on synthetic logs built from history capped at 2026-02-06 (`make_synthetic_log.py`; synthetic rows carry `synthetic=1`, real runs refuse them, and synthetic runs refuse real rows); nothing here reads UNTOUCHED.
