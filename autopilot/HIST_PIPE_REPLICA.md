## Design
Stateful, DST-aware, roll-aware re-implementation of extract.py + extract2.py + l2pre.py (kernel copied, state carried). Trading-day label = date of (ET+6h): Sun 18:00 open -> Monday, 17:00-18:00 maintenance records stay with the closing day. Per-day npz (lossless, deterministic zip): prints (ts, ts_event, px, sz, side, seq, flags, lastdep, 10-level pre-trade book), DOM counters cnb/cna, level counts tnb/tna, DepthLive/snap/row/sgn, MedLevel (EWMA 0.001), per-half-hour depth baseline rel, cancels cb/ca net of trades (pulled inputs), iceberg/sweep state, 100-ms 10-level grid, 1-ms LEVEL-1 grid (full 10-level 1-ms grid is 5 GB/week and not kept: fills deeper than L1 must use the 100-ms grid, up to 100 ms stale, or an on-demand raw lookup), instrument id per print, end-of-day state blob (resume). `unpack()` returns the replica's original names/dtypes.
Continuity rule: MedLevel, baselines, DOM counters carried across days and weeks; seeded with the first snapshot (as l2pre; C# med==0?avg). At an instrument roll the previous-snapshot/iceberg/sweep state and DOM counters are re-seeded, MedLevel and baselines kept. Month blocks start with a 5-day warm-up from a fresh state (V2 below); the very first block (2023-02) starts fresh at 2023-02-01 00:00Z (Jan 31 evening session partial).
Roll rule: instrument id present in the file (Databento NQ.v.0 volume leader, mapping switches 00:00 UTC = 19-20:00 ET inside a session, first record of the new id is a snapshot); live-platform roll rule unknown (NT8 merged history) and unverifiable on disk. Mixed-id days are flagged with change time and price jump (Sep 2026 roll on label 20260916, jump < 600 pt). The engine's bar/ET code must still handle the basis jump: common.py hard-codes ET offsets for Oct-Nov 2026 only (NOT DST-aware): any history run needs a DST-aware common.py.
