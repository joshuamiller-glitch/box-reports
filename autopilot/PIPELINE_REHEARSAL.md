## 4. Schema ambiguities found (none resolved by editing the request; options given)
1. **signals.csv required columns.** The joiner (via `shadow_score.check_signals` and the 95-field shadow_log_schema.csv) requires `ts_eval_ms, lots_research, lots_stack, live_entry_mode` in addition to the request's columns: `SCHEMA ERROR: missing required signal columns`. The request lists a smaller set. Options: relax the joiner to the columns it uses (signal_id, ts_signal_ms, book, side, taken, lots_live/lots_final, signal_px, stop_d, tgt_d), or add the four columns to the request (`ts_eval_ms` = ts_signal_ms, `lots_research`, `lots_stack`, `live_entry_mode`). Recommendation: relax the joiner (the four columns only matter to the Shadow rule scorers).
2. **fills.csv time column**: request `time_ms`, joiner requires `time` (`REFUSED: fills missing required columns ['time']`). The monitor now accepts both; recommendation: the joiner should accept `time_ms` as an alias.
3. **Order type `time_exit`** (added by the request) is not in the joiner's vocabulary: 100 rows counted as unknown -> `other`; exit class falls to `other`. Add `time_exit` to EXIT_TYPES and give it its own class (or ask the platform to write `flatten`).
4. **Fee constant**: the joiner's `FEE_PTS_PER_LOT_FILL = 0.242` is applied per FILL but 0.242 pt ($4.84) is the round-trip fee (FEES.md, harness `FEE`). Without `fee_usd` every live trade is charged twice the engine's fee (-$10,474 on 2,164 lots here, exactly). With per-row `fee_usd` there is no issue. Recommendation: constant 0.121 per fill (or require fee_usd); not changed here.
5. **Single target level**: signals.csv carries one `tgt_d` (and `stop_d`), but 70/30 split entries and the cut/profit lines can carry different levels per leg. E4 (touched-not-filled) mismatches on the synthetic data for that reason (68 of 198 touched trades did not exit at the target). Ask: log `tgt_px` and `stop_px` per leg in signals.csv or fills.csv, or confirm single-bracket semantics.
6. **trade_date type**: the request says integer YYYYMMDD, shadow_log_schema.csv says `date`; the joiner never reads it from signals (it derives it from the timestamp), so both work, but the schema field type should be stated once.
7. **Redundant stop fields**: d6_stops.csv in the request carries `join_placed_ms, join_px, join_rejected, arm`; the joiner reads only `signal_id, ts_trigger_ms, stop_level, run_past_stop_pts` and derives join facts from the `stop_join` / `stop_fallback` fill rows (and re-derives the arm). Keep them as an audit cross-check or drop them; no conflict found when they agree (they do in the rehearsal).
Also noted: LIVE_RECON-style tables use the opposite slippage sign (+ better) from stops.csv (+ adverse): already in conflict 5 of the request; the joiner's `unknown_type` counter printed 100 (item 3) and a benign warning for the extra columns `schema_ver, slice_seq`.
