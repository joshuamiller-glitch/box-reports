## ADDENDUM 1 (2026-11-19, after the first pilot month, BEFORE any recipe number was scored or published)
Pilot (TL3_EXE_L0f097450_chand3_v25_ADD_IDN, 202610, both-side stream, 36 engine trades): inert recipe == plain mf_inject trade for trade (19/19, 0 mismatched fields: criterion (1) PASS on this month). Versus the screen: exit TIME agrees (|dt| <= 3 s) in 32/33 recipe-class exits (97%, median dt 0.0 s), exit class 'Stop' as the engine names a ratcheted trailing stop fill; but exit PRICE differs by a median 1.25 pt with mean +0.17 pt (symmetric noise): the engine fills a resting stop through stop-join / book walk with latency, the screen exits at the triggering print minus 1 tick, so a 3-tick price tolerance per trade is a property of the fill models, not of the recipe logic. Amendment (stated openly, made after seeing the pilot): the per-trade criterion of (2) becomes PRIMARY = exit class and exit time (|dt| <= 3 s) in >= 95% of recipe-class exits (layer exits BookLock/StackCut/DayHalt/SessionFlat/... excluded and counted), SECONDARY = no bias in exit price: |mean(engine exit px - screen exit px)| <= 0.5 pt and per-month engine points vs screen points differences reported (not required to be within 5% because entry price conventions differ too: median entry difference reported). A family still fails if the time agreement is < 95% or the price bias exceeds 0.5 pt over the sample.

## ADDENDUM 2 (2026-11-19, still before any recipe number is scored or published)
Identity test redesigned to the strict form 'engine-with-recipe == screen simulator on the SAME entries': the screen's path walker (gcore2.walk_path, the kernel of sim_path) is replayed from each ENGINE trade's own entry fill, with the engine's tick-rounded stop / target levels (place_bracket convention), so the entry-price convention difference disappears (ex_identity.screen2). PRIMARY (gate): exit class + exit time agree in >= 95% of recipe-class exits: |dt| <= 3 s for resting stop / target fills, <= 15 s for market exits that go through the engine's request_exit latency (UWTime, ExBricks, ExLatch, RollFlat); account-layer exits (BookLock, StackCut, DayHalt, SessionFlat, ...) excluded and counted. SECONDARY (reported, not a gate): signed exit-price bias engine - screen (engine better = positive). Reason for not gating it: measured on the first 15 months per set the engine fills resting stops 1.2-1.8 pt per trade better than the screen's 'trigger print - 1 tick' convention on the both-side chandelier / clock / latch sets (~0 on the long-only latch and clock sets); that is the engine's fill model (the same one that fixed brackets and live-book stops get), so engine-vs-engine comparisons (recipe vs fixed-bracket reference rows) are on the same footing, and every published recipe number carries the bias note. Sample requirement unchanged: >= 50 stratified set-months per family before any recipe number is published (43 per set queued; both-side + mode-correct sets pool per family).
