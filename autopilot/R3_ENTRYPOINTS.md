# R3 test machinery - entry points for W-LIVEREF (live books through the same test) - W-SHORT, 2026-11-19 ~02:00Z

Research replay only. Everything below lives in code/th_short (box 1; copy synced to server 2 / Frankfurt / Singapore); data is on those servers (bars, tape, feature stores). Run on Dallas (server 2, ubuntu@207.188.7.103, full grid data) or Frankfurt / Singapore; nice 5; at most ~16 processes; NOT on box 1 (memory).
1. **Cell spec** = (session, bar row, module, variant, params JSON, bracket name, mode both/long/short). Live books: module `trig_live_seven`, variants K7 / M7 / U7 / P7 / H7 / A7 / O7, bar rows tm180 (K7), tm60 (M7, P7, H7, A7, O7), tm600 (U7), live bracket = `plain60/60` (k = 0) unless the book uses another (the grid prices every cell at the 7 grid brackets; a live bracket not in the grid needs `alts` via code/th_grid/gaudit.py).
2. **R0** (rule on the grid result): `GS_TAG=p1real python3 -I code/th_short/gsel_rule.py <sessions 0,1,2,3>` writes rule/bare_<S>.parquet (EVERY cell and its first failing rule; find the live cell there by row / module / variant) - or read that parquet directly.
3. **R2 trust** (brute force + 6 truncation cuts + fills): `gaudit.audit_cell(dict(session, row, module, variant, params, bracket, mode))` (code/th_grid/gaudit.py); returns checks, trades_L6M, avg hold.
4. **R3 stages** (30 / 200 / 1,000 same-bracket random-entry draws, equal-risk sum of R, p = (1 + k) / (1 + n)): write a CSV with columns key (session|row|module|variant|params|bracket|mode), session, row, module, variant, param (JSON string), k (bracket index: plain60/60 = 0, sym8u 1, sym15u 2, sym30u 3, asym10u/20u 4, asym20u/10u 5, asym15u/30u 6), mode (0 both, 1 long, 2 short), data_week (189), family -1, fam_rank 1, stop_pts, n0, n1; then `python3 -I code/th_short/gr3.py X <tasks.csv> 0 1 <procs>` (draws n0..n1, seeds r3rand<n>: stage A = 1..30, B = 31..200, C = 201..1000, D = 1001..10000); records land in /mnt/l2/l2vast/_grid/r3/X_*.jsonl (draws_R6 = last-26-week R per draw, draws_Rall = whole history, draws_yR = per-year R, real_R6 / real_Rall / real_yR for the real cell). p_L6M = (1 + #draws_R6 >= real_R6) / (1 + n); p_ALL likewise on Rall; p_PRIOR on min over years of R per week (weeks per year in `yweeks`). Combine with `gr3bh.combine(gr3bh.load())`. Quick one-off lists: `gr3spec.py <specs.txt> <name> [procs]` (lines `Session;row;module.variant;v1,v2,..;bracket;mode;force`) writes status_<name>.txt with the p-values at 30 draws.
5. **Calibration comparison**: the live-book rows go beside the 'CALIBRATION' table of SURVIVOR_COUNTS.md (null draw p1rand1 through the same stage A); embed your table in SURVIVOR_COUNTS.md by writing code/th_short/liveref_block.md (gladder.py includes it if the file exists).
6. Caveats: results of trig_levels_* written before 2026-11-18 06:00Z are UNVERIFIED (not relevant to trig_live_seven); draws take ~0.5 s each, ~35 s per 30-draw cell; a live book on tm60 has ~1,000+ trades per L6M so each draw is heavier (minutes).
