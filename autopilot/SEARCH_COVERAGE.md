# SEARCH_COVERAGE - what the Asia / NY AM search covers, component by component (W-COVER, read-only, 2026-11-19 ~19:20Z)

Answers autopilot/DIRECTIVE_STATUS_Q_COVERAGE_20261119_1823Z.md. Report only; nothing was changed. Evidence = the code and pages named in each cell (paths relative to outputs/). "Grid" = the big signal x bar grid (code/th_grid, W-GRIDA/B/C/D/E, scored and shortlisted by W-SHORT / W-GRIDOPS). "Ladder" = what happens to survivors afterwards (R0 to R5: bare screen, own-stop, trust, random-entry p-values, null calibration, exact engine ADD / REPLACE rows by W-ASIA / W-NYENG / W-LONENG, then W-LAYERS and W-EXITENG).

## Summary (one paragraph)

The grid varies four things at scale and nothing else: the bar (44 bar types, 494 bar-size rows in the harness at 18:13Z), the trigger (146 modules, 6,586 parameter sets, 869 variants), the bracket (7 fixed stop/target pairs in pass 2, 2 in the coarse pass 1) and the side (both / long / short), over 4 sessions. A trigger is the only entry rule: there is no general filter layer on top of a trigger in the grid. The only multi-condition entries are 2 confluence modules (69 parameter sets, fixed pre-registered k-of-N lists), plus 51 level modules (2,718 sets) used as triggers, not as filters. Everything a live book carries on top of its trigger (entry method, trade-health cuts, sizer, no-trade windows, re-entry blocks, chop gating, account rules) is NOT varied in the grid. Survivors go to the exact engine as an injected book on TODAY's stack (JL3) with a market entry at signal + 2 s, the cell's own bracket, flat at session end, and only five of today's rules acting on it (DAY-DONE 22 closes / -$4,200, day caps $12,000 / $4,800, book give-back lock, stack rule, lots table); the live trade-health, profit-lock, no-trade-zone, ATR-skip, context-cut and sizer layers do not touch it (code/th_nyeng NEW_BOOK_LAYER_FACTS.md). A book's own layers are fitted afterwards, one layer at a time (58 settings: take 12, lock 9, loss cut 4, context cut 3, own day cap 4, blackout 3, no-trade windows 5, DAY-DONE 18) but only for the top-ranked beats-live candidates (about 5 cells per session at a time; 14 cells queued 11-19 18:15Z) and still provisional (no prior-year or control results). Exits beyond fixed brackets are screened (68 recipes, 7 families) only on the D8 candidates, and 4 of the 7 families are engine-runnable today in part. Earlier programmes (T-CONFLUENCE, T-SIZER, T-ZONES, T-EARLY-CUT, T-CHOP, T-CROSS, T-FEEDS, T-UWBOOKS, T-REFIT) tested many of the missing components, but on the seven LIVE books, not on grid cells, and mostly found nothing that holds; none of those results has been re-tested on the new books.

## Ladder books: which of the components they carry

- Entry, bracket, side, session, bar, trigger: from the cell (the only things that are searched).
- Baseline layers in every engine ADD / REPLACE row (JL3, today's fixed settings): DAY-DONE, day caps 12,000 / 4,800, book give-back lock, stack rule, lots table, one position at a time, measured slippage. Not carried: no-trade zones, policy take / latch / profit locks / target shave, trade-health cuts, context cut, ATR-skip / breakout rules, governor, session lot tables, sizer (NEW_BOOK_LAYER_FACTS.md; the variants _BARE / _ACCT exist per the 1505Z order).
- Own layers (58 settings + joint): only the candidates W-LAYERS picked (first tier L01811caa x K7, L6a25b155 x K7, L5c9e11b3 x A7, L411f8593 x A7; then ranked 5 per session when the queue is below 3,000 set-months), provisional.

## Five biggest gaps (judgement)

1. No entry filter layer in the grid: confluence is 69 fixed-list parameter sets, level / regime / feed conditions are triggers only, the generic combiner was never built; the Asia / NY AM books are therefore bare triggers plus a bracket.
2. Survivors are judged against a fixed stack with only five account rules acting on them (DAY-DONE alone skipped 334 of one book's signals), and the layers that make the live books work (trade health, profit lock, no-trade zones, sizer, re-entry block) are fitted only for a handful of top candidates; account protection is refit only in the later joint stage.
3. Exits: fixed brackets only in the grid; the 68-recipe screen runs only on D8 candidates (London 0), 4 of 7 families are not engine-runnable (staged, order flow, SAR, plus most trails), so a book whose real edge is in its exit would not be seen.
4. Entry method, sizer, re-entry and market-type gating are not varied for new books at all; everything earlier is on the live seven and mostly null, so the new books have neither the live layers nor tested substitutes.
5. Search-level evidence is thin where it matters: pass-2 (full parameter grid, all 7 brackets) is not complete for all modules, level results were stale until a 11-18 re-run, calibration shows null equal to real for zones, order book, tape and cross-market families, and the engine ladder has no completed prior-year, 30-control or 2-week-roll results for layered books yet.
