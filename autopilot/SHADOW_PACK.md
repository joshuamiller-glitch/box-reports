## 2. What the sizer lines are
Both are research lines that change only the SIZE of a signal the box already takes; neither touches entries, stops or targets. Shadow means: for every LIVE-SESSION signal (the signals the box actually sees: 27,902 of the engine's 88,490 rows; it fills about 21,400) the line writes the multiplier it WOULD have applied and the lots that would have resulted; the weekly runner replays the REALISED P&L of the box's real trades with the would-be lots.
**VT_Q1A (ZL-1, SIZER_Q1A_VT; near-miss, `SIZER_LEAD_REGISTER.md`, `DS3_SIZER_FINAL_DRAFT_S4A.md` section 3):** m = clip(Q1A x min(1, max(0.5, M20 / ATR14_5m)), 0.25, 1.0). Q1A = the box's ER ladder multiplier (ER(20) of 5-min bars < 0.30 -> x0.5, else x1.0, NaN x1.0). ATR14_5m = Wilder ATR(14) of the 5-minute bars, value after the last 5-minute bucket CLOSED at the signal second (bucket end <= signal second), SMA seed of the first 14 true ranges (continuous series, the prior bucket close enters the true range across gaps). M20 = median of the finite ATR14 values of ALL 5-minute buckets of the 20 label days before the signal's label day (days with at least one bucket; the bucket's label day is the day of its END; NaN unless more than 500 values). f = 1.0 if M20 or ATR is NaN. Down-only (m <= 1). Research: genuine PA9 L6M / PRE / MID / X' 32.9 / 30.6 / 21.9 / +16.1, carry-dropped L6M 35.7 / PRE 17.4, ts2 mean lots 1.850 vs Q1-A 2.139 (-13.5%), total -$341k; NEAR-MISS not flagged (matched-lots random-drop rank .55 on L6M and 1.00 on PRE, family null p .30, PE carries it, unstable walk-forward, positive dollar months 15 of 43).
**Z3_RVD30 (Z3, SIZER_S3 3.2 pair, rule PROD; `DS3_SIZER_FINAL_DRAFT_S4A.md` 3a/3b):** m = clip(clip(M_rv x M_d30, 0.25, 2.0) x Q1A, 0.25, 2.0). rv_pct_5d = percentile of the 5-day mean of the daily realised variance (sum of squared 1-minute log returns of the label day) of the last COMPLETED label day, among the previous 252 days (needs 60 finite earlier values); delta30_s = the 30-second signed aggressor volume (buy_vol - sell_vol over [p-29, p]) times the signal side, CAUSAL: the window ends at p = the last print second STRICTLY BEFORE the signal second (NaN if the L2 table has no row for second p); each feature is turned into a per-book EXPANDING RANK among earlier LIVE-SESSION signals (strictly-below share; >= 100 earlier valid values; the value is inserted after it is ranked; ties by arrival order), r' = 1 - rank (direction -1). M_rv = 0.5 if r' < 1/3 else 1.0 (map D3, pair A); M_d30 = 0.5 if r' < 1/3, 1.0 if r' < 2/3, else 1.5 (map L3, pair A); NaN rank -> 1.0. Research (Z3 corrected LIVE4 rows, `SIZER_S3`): genuine PA9 L6M 26.4 / HOLD 1.9 / MID 25.8 / PRE 26.2 / X' 10.3, carry-dropped L6M +9.6 / PRE +6..+8, mean L6M +3.3k and PRE -1.5k per week, placebo L6M ranks .81-.86 (not clean), worst day 26 lots / $31.2k vs Q1-A 18 / $21.6k (+44%), multiplier up to x2.0 (it can ADD lots; it is not down-only). Z2: not a candidate, WATCH only.

## 3. Exact specification of the two sizer lines
### 3.1 Inputs (from the box; nothing else)
* Per live-session signal (when the box sizes it): signal second s (epoch), book, session, side, the label day, `q1a_mult` (the ER multiplier the box applied), `lots_l1` (lots after session x A06 slot x B02, ONE rounding), `zone_half` (0/1), `lots_actual` (the lots the box used) - the box's own lot order is session -> A06 slot -> B02 -> ER multiplier -> zone HALF last, each stage rounded `max(1, floor(x + 0.5))`.
* The tape: 1-second prints (hi, lo, last) -> 1-minute bars (key = epoch minute; bar end = (key+1) x 60) -> 5-minute buckets (key // 5); and the L2 one-second table rows (ts, buy_vol, sell_vol) with `ss = ts // 1e9 - 1` (the print second the bin state describes; first occurrence of a duplicated ts).
* Prices in the continuous (roll-adjusted) series; ATR and ranks use differences/ratios; the realised-variance returns use log levels, so see 3.5 for the frame note.
### 3.2 Order of evaluation at a live-session signal (second s) - the unit-test contract
(a) every 1-minute bar with end <= s has been pushed (`TapeState.push_minute`) and every 5-minute bucket with end <= s is closed (`TapeState.advance(s)`; the bar containing s is NOT used); (b) the L2 ring holds the table rows with ss <= s - 1; p = the last print second before s; (c) VT: f and m from ATR14 and M20; (d) Z3: rv_pct_5d from the completed days, delta30 at p x side, then BOTH ranks are read and the two values inserted into the book's lists (live-session signals only, whether or not the box takes the trade), then the mapping, PROD, m; (e) would-be lots `lots_would = max(1, floor(l1 x m + 0.5))`, then if zone_half `max(1, floor(. x 0.5 + 0.5))`; (f) write the signal row (3.4) at s; when the box's real trade of that signal closes, write the fill row. Both lines are independent; the order VT then Z3 is fixed only for the log.
### 3.3 State and cost
TapeState: current minute/bucket, ATR (2 floats), ATR value lists of the last 21 label days (about 5,800 floats), the daily realised-variance list (300 days), one open day accumulator; Z3: per book two sorted lists (rv, d30) of up to about 8,000 values; ring: 30 seconds. O(1) per bar and O(log n) per signal; a few MB.
### 3.4 Log schema (forward_register/sizer_shadow/; ZL-2 `shadow_register` style: append-only CSV, join on sig_id)
`<LINE>_signals.csv`, LINE in VT_Q1A, Z3_RVD30, one row per LIVE-SESSION signal: sig_id (`<LINE>_<book>_<signal_sec>`), ts_signal_utc, line, book, session, side (+1 long), label_day, q1a_mult, lots_l1, zone_half, lots_actual, mult_would, lots_would, lots_delta (would - actual; negative = the line would have cut size), then the inputs: VT: atr14_5m, m20, f_vt; Z3: rv_pct_5d, delta30_signed (side-signed window sum), delta_ring_sec (p, epoch), rk_rv, rk_d30, m_rv, m_d30, prod; definition_version (`sizer_shadow_v1`), logged_by. Blank = not applicable / NaN.
`<LINE>_fills.csv`, written by the box when the REAL trade of a logged signal closes (taken signals only): sig_id, ts_exit_utc, lots_filled, usd_actual (after the live cost basis), net_pts_per_lot (= usd_actual / (20 x lots_filled)), note.
Writers: `sizer_lines.log_signal(dir, line, sec, book, session, side, q1a_mult, lots_l1, zone_half, lots_actual, res, tape, ld, dsig, delta_ring_sec)` and `sizer_lines.log_fill(dir, line, sig_id, ts_exit, lots_filled, usd_actual)`. Seeds for a cold start (`make_seed.py`, forward_register/sizer_shadow/seed/): `rv_seed.csv` (label_day, rv: the last 300 daily realised variances, research frame, to the cap 2026-10-30) and `rank_seed.csv` (book, kind rv|d30, value: all earlier live-session values, 55,436 rows). The ATR/M20 state is rebuilt by replaying the 1-minute bars of the previous 36 calendar days (at least 22 label days).
### 3.5 Roll, holiday, restart, frame
* **Roll:** `TapeState.roll_adjust(delta)` adds delta (new minus old contract close at the same minute) to the stored prices (previous 1-minute close, open bucket high/low/close, prior bucket close); ATR, M20 and the rv/percentile history are untouched. Test (30 random rolls of +-20..300 pt, 660 signals): ATR14 after the roll identical in 660 of 660, rv_pct_5d unchanged.
* **Restart:** replay the bars of the previous 36 calendar days, load the two seeds plus the Z3 values already in the forward signal log (rank lists), then resume; test: 15 random cold starts, ATR14 and M20 at 360 later signals identical in 360 of 360. Live-session signals missed during a downtime are missing from the rank lists (log the downtime).
* **Holidays / halts:** days with fewer than 500 finite ATR values in the 20-day window give M20 = NaN -> f = 1 (no change); the label-day rule is the one of fade_books (ET date of wall clock + 6 h).
* **Frame (rv_pct_5d):** the research realised variance is computed on the back-adjusted price path (levels up to 3,700 points above the raw contract in 2023), so recent days in raw levels have a slightly larger variance for the same point moves; the live line starts from the seed (research-frame values to 2026-10-30, offset to the raw contract about 4 points now) and then uses the live continuous series: expect a small upward drift of the percentile of new days (a few percent at most; the roll offsets in 2026 were 300-800 points on 25,000-30,000). The M_rv state (0.5 only in the lowest third of the inverted rank) therefore trips slightly less often than in the research; not corrected.
### 3.6 Lots
`lots_would` is exactly the research function `sizer3_ts2.lots_ts2_m` (live order, zone HALF last): identity test over all 88,490 engine rows: 0 mismatches for the actual Q1-A lots, for the VT would-be lots and for the Z3 would-be lots. Mean live-row lots: Q1-A 2.075, VT would-be 1.750 (-15.7%), Z3 would-be 1.977 (-4.7%). Z3 can ADD lots (up-size on 18% of taken signals in the research, down-size on 20%).

## 5. Weekly replay runner and verdict rules
`code/zones3/sizer_shadow/sizer_forward_weekly.py [--regdir forward_register/sizer_shadow] [--start 2026-11-04] [--week N] [--selftest]` (called by monday_all.py; writes SIZER_SHADOW_WEEKLY.md, one `SIZER SHADOW week N` line to MORNING.md when run alone, and last_week.json): per line the number of live-session signals (week / cumulative), the share of signals whose lots would change (research on the engine's taken trades: VT 18.3% all down; Z3 40.9% = 19.6% down + 21.3% up), mean lots actual -> would-be, and on the box's REAL trades: the replay delta = sum of lots_delta x net_pts_per_lot x 20 (week, cumulative), the weekly cumulative path of actual and would-be P&L since the start and the maxDD of each (a cut of the realised drawdown shows once a drawdown exists), and the formula check lots_would = max(1, floor(...)) on every logged row.
**Verdicts:** MECHANICS = share of taken signals changed vs the research 2026 rate with a 90% binomial band (IN BAND / OUT OF BAND; needs 30 taken trades) - this catches an implementation that does not behave like the research; EFFECT = EARLY (keep logging) before week 13, INCONCLUSIVE after: a sequential test of the selection gain is not available. The per-signal selection gain (dollars saved by cutting the trades that lose more than average) has a research mean of +3.5 $ per taken signal for VT in 2026 (sd 603) and -16 $ for Z3 (sd 1,065, i.e. no selection benefit); the log-likelihood gain per signal under H1 = the research mean is mu^2 / (2 sd^2) = 1.7e-5 for VT, so the +-2.2 bound needs about 128,000 signals (the box takes about 7,000 signals a year): the line cannot be decided on its own forward record; what the register gives is the replayed realised P&L and drawdown with and without the line on real trades, to be compared with the research rows at the first real drawdown episode. Research expectation of the replay delta on the engine's taken trades (old-base flat dollars, 1 lot scale): VT -$313k over all history (-$78k in 2026), Z3 +$133k (+$88k in 2026): VT trades mean for drawdown, Z3 raises the mean and the worst day (+44%).

## 6. Known limits and decisions needed
1. The box must expose per signal: q1a_mult, lots_l1, zone_half, lots_actual, and write a fills row at the close of every real trade (usd_actual, lots_filled): without the fills file the replay delta is empty (the lots and multiplier columns are still comparable to the research).
2. Aggressor volume: delta30 is built from the L2 table buy_vol / sell_vol; D7's tape must supply the same per-second totals (tolerance: ranks, not values).
3. rv_pct_5d frame drift (3.5) and the previous-print-second rule for the delta window (the window ends at the last print second before the signal, not at s - 1).
4. Z3 can add lots: the Shadow only records the would-be lots; the +44% worst day is in the research record.
5. The ER multiplier and lot order are the box's (ts2, Q1-A); if the box changes the ladder the research arrays (and this spec's Q1A input) change with it.
6. No PASS claim; both lines remain NEAR-MISS / WATCH.
