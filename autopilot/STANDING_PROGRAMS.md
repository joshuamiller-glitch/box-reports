## 1. Monday runner (monday_all.sh -> monday_all.py)
Every Monday 13:00 UTC it calls, in this order, with --morning pointing to a scratch file (the runners still write their own detail pages and csv, but not MORNING.md): `zones3/bt_forward_weekly.py` (BT flip; log forward_register/bt/bt_flip_shadow.csv, else forward_register/bt_flip_shadow.csv; --start 2026-11-02), `zones3/nyam/nyam_forward_weekly.py` (NY-AM fades bundle ONRTH/VWAPF/ORBF at 0.5x; --regdir forward_register/nyam; --start 2026-11-04), `zones3/fade_shadow/fade_forward_weekly.py` (top-3 fade bundle VB2NYPM_T1 + PDASIA_T2 + VB2NYAM_T3, optional OR15NYAM_T2 REGIME line; --regdir forward_register/fade; --start 2026-11-04), `zones3/nyam/nyam_regime_monthly.py` (self-gated: prints only on the first Monday of the month). It appends ONE block to MORNING.md: `## <ts> MONDAY ALL (week N since 2026-11-02 ...)` with one bullet per source (the runner's own line, or `ERROR rc=...`, or the 'log not found / register empty' line) and a runner-status line. Idempotent per day (state file); `monday_all.py --dry --force` prints the block without writing (tested 01:12Z: all four runners rc=0, registers empty, BT log not yet present). Detail pages: BT_FORWARD_WEEKLY.md, NYAM_FORWARD_WEEKLY.md, FADE_FORWARD_WEEKLY.md.
**One writer:** `nyam_weekly_loop.sh` (pid 3582265, CAL) was STOPPED at 01:13Z and its job is done by this runner (CAL informed); `fade_weekly_loop.sh` was never started; there is no BT loop. `zones3/fade/fade_loop.sh` (pid 3622106, CAL: rebuilds DS3_FADE_RANKED.md every 2 h) is a different job and stays.

## 2. THP_POLICY refit (23:00Z daily)
S5's `exit_loop.sh` (pid 3063277, cwd zones3_s5, started 2026-11-02 14:07Z) runs `exit_integrator.py` every 1,500 s: it rebuilds autopilot/DS3_EXIT_N.md and autopilot/THP_POLICY_D7_N.txt from the family pages DS3_EXIT_N_LOSS / TIGHTEN_SCALE / TAKE / FLOW (RETARGET_TIME) .md. Confirmed ALIVE at 01:10Z: THP_POLICY_D7_N.txt rewritten 01:07Z. `thp_daily.py` at 23:00Z (1) checks that loop (restarts `./exit_loop.sh` if the process is gone; runs the integrator once if the policy file is older than 40 min), (2) counts the non-comment lines of THP_POLICY_D7_N.txt per section (entry/profit/loss/bracket) and appends `THP policy refit (daily 23:00Z): lines passing on N: none (0) / <n> [first lines]; sections ...; refreshed X min ago by S5 exit_loop.sh (pid, alive); family pages <mtimes>; file status: <STATUS line>`. Dry run at 01:12Z: `lines passing on N: none (0)`, status 'NO LINE PASSES ON N', family pages last updated 11-02. The rule for 'passes on N' is in DS3_EXIT_N.md (the integrator applies it; this stamp only reports the result).
(The live THP_POLICY_D7.txt is never touched by these programs.)

## 3. Ledger monthly refit
`ledger_monthly.py` on day 1 of the month (once per month, state file; --force to run now): archives the previous /mnt/l2/l2vast/ds3_base4/lvs_q to lvs_q_<month>, then with 3 shards `LVQ=1 layer_vs_size.py k 3` (100 same-count + 50 stratified random half-lot layers, each scaled to the shipped worst-20, frames lock none and 12R), `LVQ=1 lvs_an.py` -> autopilot/DS3_ZONES_LAYER_VS_SIZE_TS2Q1A.md, `q_layers.py` (none / shipped / sA40 / nA60 / PUL k3 4h AH D20 / ALL7 cubes, both frames) -> `composite_q.py` -> autopilot/DS3_ZONES_COMPOSITE_TS2Q1A.md, and appends a `LEDGER REFRESH` note to MORNING.md (steps and return codes, layer-vs-size answer sentence, composite shipped-vs-none cut, changed/unchanged vs the previous refit). Waits while less than 15 GB RAM is available; 3 workers.
**Base:** `d7base/lvq.py::run_q` = `run_v13t_ts2` (ladder Q1-A: session -> A06 slot -> B02 -> ER Q1-A -> zone HALF last), verified: run_q({}) is bit-identical to run_v13t_ts2({'ladder':'Q1A'}); zone=False (no layer) zeroes all four zone masks; a placebo mask patched into D._zone_masks reaches the lot table (the ts2 zone-HALF rounding cache d7_v13t._LIB['rz'] is cleared on every call); lscale works. Smoke (6 A + 3 B draws, 3 shards): 2.3 min, so the full 300 jobs take about 40 min. Headline numbers on this base (smoke): shipped layer L6M +27.0k/wk maxDD 104.8k, HOLD 22.6k/122.0k, PRE 13.2k/88.2k; no layer 26.0k/122.3k, 22.5k/122.3k, 12.8k/98.3k.
**Not included** (kept as manual): CRT4h Z2-mask candidates in the composite (needs Z2 masks on this base), the leave-one-out and consistency passes (lvs_loo.py, lvs_cons.py: LVQ branch added, run by hand). The job does not refresh market data or the engine caches; it re-reads the base as it stands (the research cap moves with the pipeline, memory: cap 2026-10-31).
A first forced refit (baseline) ran 01:21Z-01:36Z (15 min, rc 0 on all steps; the 300 random layers took 14 min on 3 workers) and wrote both TS2Q1A pages plus the LEDGER REFRESH note and an addendum in MORNING.md (the first note's answer field was empty because the parser looked for a section the generated page does not have; fixed).
