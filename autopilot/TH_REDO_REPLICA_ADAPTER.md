## 1. Interface the programs need, and what the adapter provides
`ReplicaAdapter(asof).run(rule)` -> TradeFrame: tid, book (KB/PE/SM/HM/MV/PB; replica K7/P7/U7/H7/M7/A7), session (entry session), entry_ts, exit_ts, lots, pnl_usd (gross, the replica headline basis; `pnl_net_fee` beside), cut (bool), cut_kind (ThL2Cut | PolicyCut), exit_kind, label_day (ET trading day, +1 from 18:00), iso_week, flags win_L1M win_L2M win_L3M win_L6M win_HOLD (windows_asof(asof), same formula as th_redo/score.py) win_MID win_PRE win_X' (instr2_eval fixed) and win_PRE_CAP (after the research cap: in no window). `.attrs/meta` label PRE-PROOF. Same method names as adapter.py (baseline, run, screen, live_week); `placebo` raises NotImplementedError (placebos run on the per-trade path in score.py, not in the engine). base/fill/phase arguments are accepted and ignored: the replica has ONE fills model (literal book walk, 1.0 s latency, no calibration) and no lock-reset phase, so the plan's 36-run ladder (9 phases x 2 bases x 2 fills) does not exist on this engine - see section 2 and the proposed addendum.

How the rule is substituted (no copy of the C#; the replica's own manage_th_l2 / manage_policy run unchanged): TH[LOSS_MIN]=arm, TH[PULL_MULT]=multiple, TH[PULL_SECS]=window (pulled-support window and new-extreme window), and the policy loss line becomes pct <= -arm/60, pulled_mult >= multiple, secs_ext <= window. Persistence N and the extreme variant are filters on the cut the literal code wants (the exit request is intercepted, the side effects undone if the filter says no; N = consecutive 1-s-throttled evaluations on which the condition held). Rule keys: arm, mult, win, pers, ext (0 live = new adverse extreme within win s; 1 = also at the extreme on the deciding print; 2 = no new-extreme condition), books, sessions or unit ('KB_asia'; applies by book and entry session; other trades keep the live cell), and `policy` = list of policy-file lines that REPLACE the loaded ones (the C/E/F route: cut/take/tighten with features pct, mins, secs_ext, pulled_mult, tot_rel, ahead_rel). Same entries, same fills, same sizing, locks, caps and re-entries after a cut (all the replica's own, so re-entries exist, which the old engine lacked). None = HOLD = the literal live cut with no substitution code in the path.

Settings of the iter12 headline (verified exact): sim.PRM defaults + `SS_RULES=True, SS_SET='code4', L2PRE='_c2', WARM_START=''` (exported as ITER12_PRM; they were not recorded in run_replica's call, found by trying the registered variants: SS code4 slots, c2 L2 arrays, warm-up from 09-01 = the default WARM2 file; WARM_START 09-01 given by the filter changes only X4, 2 trades, +6.8k).

Open definitional points (flagged, not decided): (a) the grid's `ext` {off,on}: the live cut already requires a new adverse extreme within the window; the adapter maps live = 0, stricter = 1, none = 2 - the prereg needs one sentence naming the reading; (b) A5 lot-scaled arm (needs lots at evaluation time, one line in the wrapper), A2 flip triggers (features exist in l2pre: imbalance, iceberg, delta turn, sweep arrays), A4 blackout (the replica has a BLACKOUT_BOOKS/MINS mechanism, U7 only; generalising is a parameter change in TH), A6 dwell = persistence with a level (same filter). Not yet wired: B (L1 path rules: not in DS7.cs, no C# to port; implementable as the same probe filter using adv/fav extremes and the price path), D (profit trail/chandelier/ATR/time decay: the replica has the policy trail and the old-panel profit tighten only), G (needs per-evaluation rows: the Tier-S recorder below gives them for the loss side).

## 2. Cost per run, and how to evaluate thousands of cells
Measured (blind week, 2,316,491 prints + 7.65 M warm-up prints, 13 books, 32-core box, MemAvailable 129 GB): load 10 s, event loop 14-16 s = about 165 k prints/s; one full HOLD run 27 s cold, 15-16 s with the loaded arrays shared by later runs (the adapter caches the read-only arrays); peak RSS 9.3 GB (5 GB of it is the 1-ms book grid e2_grid1ms.npz). Extrapolation to 2023-04..2026-10: about 950 sessions x ~0.46 M prints = about 440 M prints = about 45 min per full-history cell on one core, plus the data pipeline of section 3. At 550 Tier-1 finalists (plan) x 1 full-history run = about 410 core-h (plan budget 99 core-h assumed 33 s/36 runs on the old engine); Tier 2 x 1 run = 1,600 x 0.75 h = 1,200 core-h: not feasible at that size on one engine tier. Proposal:
* Tier S (stage 1, every cell, implemented and tested): ONE HOLD pass records, per ThL2 evaluation of an open trade at <= -15 pt, a feature row (time, book, entry, side, qty, unreal, med, secs_ext, at-extreme flag, pulled support for windows 2/3/5/10/15 s, print index) = `run(None, record=True)`; blind week 17,421 rows (3.3 M rows for 3.7 years, 150 MB). A cell (arm, mult, win, pers, ext) is a pure filter on those rows: first firing row per trade, microseconds per cell; the fill price at fire+1.0 s is one book walk per fired row (100-ms grid). Self-test: the filter at the live cell reproduces all 99 replica ThL2Cut times exactly (99/99). Approximation, stated: entries and later trades are held fixed (no re-entry/lock/size cascade after a cut), as in the old screen; the pulled/med/L2 arrays do not depend on the rule, so nothing is approximated inside a trade. It is the analogue of the old loss-row replay (159 cells/s) at replica fidelity, so the family nulls (W_fam = 200 worlds over 134 k unit-cells) stay on this path.
* Tier F (finalists): full replica re-run with the rule substituted (cascade included), per-month chunks run in parallel with warm-up prints (section 3). Cost scales with the NUMBER of finalists x 45 min: Tier 1 at 150 + 100 x 4 = 550 needs about 410 core-h; at 8 workers x 9 GB about 52 h wall. Proposed cut: Tier 1 to 40 per program (200 total = 150 core-h, about 19 h wall) - this is exactly option (c) of plan section 4, needs the addendum.
* Per-book independent replay is NOT exact: books share the signal engines, the stack rule, the week floor and the 70/30 add; the cheap per-book path is Tier S, the exact path is the whole-stack run. Per-print L2 features (snapshot, pulledLog, MedLevel) are computed once per day in the data pipeline and are rule-independent (verified: only TH constants and the cut condition touch them).
