## P9 trend-day call (causal; 1-min bars of the closed minute + this run's own closed trades of the Globex day)
side = sign(close - mean of 1-min closes since 18:00 ET). K3 hold: last H=45 closes all on that side of the running mean by >= 0.05 x expR; K4 range: day range so far >= 0.6 x expR (expR = median range of the previous 20 Globex days); K1: >= 2 closed Target winners on that side today; K2: >= 1 closed counter-side trade today, counter closed net <= 0 and with-trend closed net > 0.
Call definitions: C1 = K3&K4, C2 = K1&K3, C3 = K1&K2&K3, C4 = >=3 of 4 incl K3, C5 = all four.
Actions once called (with-trend = same side as call; applies to all books): a_ct block counter-trend entries; a_sz lots x1.5 with-trend; a_szcap lots x1.5 and STACK same-side cap +4 lots; a_tg target x1.5; a_tg2tr target x2 + trail (peak >= 0.6 x original target, exit on 40% give-back of peak); a_lift day-profit cap off and give-back keep 0.7 with-trend, plus un-halt of with-trend entries after a profit-type halt; combos: c1 = ct+szcap+lift; c2 = ct+tg1.5+lift; c3 = ct+szcap+tg2tr+lift. Cells TL3_TD_<C>_<action> (5 x 9 = 45). Placebos: call table of the real cell shifted 11/23/37 business days (same clock time of day), same actions (TL3_TD_PLk_...).

## ADDENDUM A (written before any P9 engine cell was scored; sha logged in DECISIONS.md)
The call parameters in the first draft (H=45, dist=0.05, r=0.6) fired on 90% of days for about 1,000 minutes a day (base-world dump, 43 months): not a trend-day call. They were re-chosen on X' ONLY (2023-04..2024-09; offline, code/th_trendevent/td_tune.py, table /mnt/l2/l2vast/_trendevent/an/tune_xp.csv) by hindsight precision (call day == close-open trend day, range >= expected) and the static base P&L after the call, then FROZEN for every other window: H=90 min, dist=0.15 x expR, r=1.0 x expR, n1=2. Consequence stated up front: X' is in-sample for the CALL parameters (not for the actions); L3M, L6M, HOLD, GAP, PRE are out-of-sample for them. A causal call fires late (median first call 10:00-12:00 ET for the price-only definitions): that is the cost of being causal. Everything else in the prereg is unchanged.

## ADDENDUM B (before any P9 engine cell was scored)
JN05W2 (live panel base + F3 + E1 + C22 + BR3S + FLAT45K) contains NO same-side STACK lot cap (the JN04 layer STACK cap 6 London is not in it) and no 'lot cap x1.75' parameter in the exact engine; what limits a stack there is: one position per book, per-book day profit/loss caps (K7 12k/4.8k, M7 12k/4.8k, U7 24k/9.6k, P7 42k/8.4k, H7 24k/9.6k, A7 6k/2.4k), the BookLock give-back (2R arm, keep 0.5), the session lot table, the C22 / E1 governors and the time blocks. The action 'szcap' (size x1.5 plus STACK cap +4) is therefore replaced by 'sz2' (with-trend lots x2.0); the 'cap' option in the hook stays inert. All other actions unchanged. The user's 'STACK cap 10 / lot caps x1.75' are live-panel numbers I could not find in the engine; the page says so.

## ADDENDUM C (before any P9 cell was scored; the only P9 engine run so far is a 202610 debug run of TL3_TD_C2_c3, discarded)
The debug run showed that the 'lift' action as drafted (give-back keep 0.7, copied from the G3 convention) TIGHTENS the lock (halt when day <= 0.7 x peak), the opposite of relaxing DAY-DONE, and that an un-halted book re-fired the old peak at once (28 re-entries and exits in one month). Fixed before scoring: lift = day-profit cap off while called and give-back keep 0.3 (halt only when day <= 0.3 x peak, i.e. 70% of the peak may be given back) for with-trend books; un-halt re-arms the lock peak at the current realised day P&L (same re-arm convention as the cde lock rule). Actions ct, sz, sz2, tg, tg2tr unchanged; combos c1-c3 use the new lift.

## ADDENDUM D (before any of these cells was scored)
Two actions added to the P9 grid because the order is 'capital intact until a trend day is called, then press': pr1 = entries while NOT called at lots x0.75, with-trend entries once called at x1.5; pr2 = uncalled x0.5, with-trend called x2.0 (counter-trend entries keep x1 and are not blocked). ## ADDENDUM E (gate definition, written after seeing that several L3M cells leave the one-week L3M max DD unchanged)
The tolerant gate stays as in the prereg; the 'at least one window with a drawdown cut' clause is read as: a drawdown cut larger than 0.5% in some window OR a mean gain larger than 3% of the reference mean in some window (equal-drawdown mean gain), because recent max DD is one week (W44) that call-based rules cannot touch. Leads are labelled by which clause they pass. Promotion to later windows uses the same gate on the windows already scored (all weeks or W44 removed).
