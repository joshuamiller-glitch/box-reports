## 1. Definition (what the exact engine does)
- **Scope:** K7 only (as scored). One shot per trade: after it fires or the trade exits otherwise it is done. Applies to the whole open position (`pos_qty`), all lots; no partial.
- **Trigger quantity:** x = side * (mid_r - entry_px), in index points, where mid_r = the 1-second state-base mid = (best bid + best ask)/2 of the top-of-book snapshot at the close of second r (th_state.py `D['mid']`; NOT last trade price), and entry_px = the book's CURRENT FILL AVERAGE (after the 30% resting add has filled, the average of both fills; same quantity the live ThL2 panel measures `unreal` from). Fires when x <= -45.0 (inclusive).
- **Decision second:** evaluated on completed 1-s rows only. The hook runs inside the per-second loss-cut evaluation (`manage_th_l2`, after the base state cut ran), walks every completed row r since the last call and decides at the CLOSE of row r. Rows before the entry second are ignored (first row = first second at/after entry_ns).
- **Fill model:** market exit event at the next row: t_ev = max(ts[r+1], now); price = mid_{r+1} - side*0.80 pt (long sells 0.80 below the mid, short buys 0.80 above). Engine continuity value; the live loss-cut measures 1.19-1.20 adverse, so each cut saving is overstated by ~0.4 pt (~$8/lot/cut). No joining, no limit, no queue: always a market order, exit name `EarlyCut`.
- **K7 state/loss-cut line:** STAYS ON. LPB_BASE keeps the K7 state cut (arm 45 pts, 10x, window 2, persistence 3, var 2, newmae 0 per unit K7_0..5) and the P7/M7/U7/A7/stack/lock lines unchanged. The flat rule is an extra unconditional line; whichever fires first exits. 177 of 603 L6M flat exits had a StateCut twin in LPB_BASE (the state line would have cut the same trade anyway; typically 0-60 s later, same area), so the flat rule mainly adds the cases where the state line's pull/persistence conditions are not met.
- **Composition with the native stops:** the flat cut (-45) sits inside the worked 60-pt stop (PumpStopExit, K7 = JoinThenMarket) and the 80-pt native catastrophe stop. When it fires it cancels `stop_order`, `target_order` and any stop-join order, then `exec_exit('EarlyCut', price, pos_qty)`; the 60/80 levels never trigger afterwards. If the stop worker or an earlier exit is already running (`exit_pending` or `stop_triggered`), the flat check is skipped. The 60-pt worked stop and the 80 catastrophe stop remain as backstops (they only act if the flat exit did not happen, e.g. a gap through -45 inside one second still exits at mid_{r+1}-0.8, see row D).
- **Targets/adds:** the 60-pt target (re-based after the add) is unchanged and is cancelled with the flat exit; the resting 30% add limit (3 pt against) is disarmed by the exit like any exit.
- **Measured outcome (L6M 2026-05..10, 603 K7 flat exits):** adverse excursion at exit (exit_px vs final average) median -46.3, IQR -47.55..-45.55, min -59.3, max -34.8 (the -34.8..-44 cases are trades where the average moved after the add; the hook measured against the average at the decision second).
